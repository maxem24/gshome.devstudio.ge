# Объявление или выдача по ссылке (myhome, ss.ge)

Дата: 2026-10-29. Заказчик — владелец GS Home. API делает Real Estate, экран — GS Home.

## Зачем

Агенту присылают ссылку: на объявление или на выдачу сайта. Сейчас он руками переносит её в
фильтры «Найти квартиру», а объявление, которого нет в базе, найти не может вовсе (решение
27.10 — «позже, нужен API в Real Estate»). Нужно: вставил ссылку, нажал «Обработать»,
получил объявление в нашей базе или сохранённый поиск.

## Как выглядит в GS Home

- В шапке рядом с «Найти квартиру» кнопка «По ссылке». Она открывает окно с полем для ссылки и
  короткой подсказкой: какие сайты принимаем и что будет с объявлением и с выдачей.
- **Объявление уже в базе Real Estate** — сразу открываем карточку (`ListingView`).
- **Объявления в базе нет** — сборщик откроет карточку. Окно закрывается с тостом «Ставим в
  работу». Когда готово, приходят колокольчик и тост на 10 с со ссылкой на карточку, как у «Собрать
  полную информацию».
- **Ссылка на выдачу** — обычный поиск из «Моих поисков»: страница результата, опрос, колокольчик.
  В подписи поиска вместо фильтров стоит «Ссылка myhome: …». Фильтры сайта, которых у нас нет
  (животные, парковка и т. п.), применяет сам сайт: сборщик обходит выдачу по ссылке как есть,
  поэтому найденное уже им соответствует. «Повторить» отправляет ту же ссылку ещё раз.
- Кнопку видно, только когда `GET /me` отдаёт непустой `imports`. Пока Real Estate его не
  выложил, кнопки нет.
- Направление: сделка, которую Real Estate распознал в ссылке, становится направлением поиска
  (на сайтах искать в другом направлении можно, 27.10). Не распознал — направления агента.

## Контракт API Real Estate

### `POST /api/v1/imports`

Тело: `{"url": "https://www.myhome.ge/…"}`. Язык текстов — `lang` в query (`ru|en|ka`), как у
`GET /search-jobs/{id}`.

Сервер сам определяет сайт (`myhome_ge` / `ss_ge`) и тип ссылки: объявление или выдача.

**Ошибки**

| код | когда | что делает GS Home |
|---|---|---|
| 422 `validation_failed`, `error.fields.url[]` | не наш сайт, страница не распознана (главная, профиль агента), выдача не сужена (без города) | показывает текст `fields.url` как есть (как у района 29.10) |
| 429 | лимит; выдача делит лимит с `search-jobs` | «Слишком много поисков» |
| 503 `refresh_busy` | новая карточка: потолок общий с актуализацией (как у `POST /listings/{id}/refresh`) | «Сборщики заняты» — тот же текст, что у кнопки актуализации |
| 503 `collectors_offline`, `site_paused` | для сайта нет сборщика на связи; сайт на паузе или выбран дневной лимит (время — в тексте) | текст `error.message` |

**Ответ, объявление** (`kind: "listing"`):

```json
{
  "kind": "listing",
  "id": "uuid импорта",
  "source": "myhome_ge",
  "external_id": "21345678",
  "url": "нормализованная ссылка",
  "status": "done | queued | running | failed",
  "listing_id": 123,
  "message": "Текст для человека"
}
```

- Объявление уже есть в базе (по `source` + `external_id`) — сразу `status: done` и `listing_id`.
  Задание сборщику не ставится: свежесть даёт кнопка «Собрать полную информацию».
- Нет в базе — задание `card` по ссылке, без нашего id. `status: queued`, `listing_id: null`.
- `failed` — карточку не открыли или объявление снято. В `message` причина для человека
  («Объявление снято с публикации», «Сайт на паузе до 14:30»).

### `GET /api/v1/imports/{id}?lang=`

Тот же объект, что и в ответе `kind: "listing"`. Чужой или устаревший id — 404. Опрос раз в 10 с;
хранить хотя бы сутки.

**Ответ, выдача** (`kind: "search"`):

```json
{
  "kind": "search",
  "source": "ss_ge",
  "url": "нормализованная ссылка",
  "filters": {"deal_type_id": 2, "property_type_id": 1, "city_id": 1},
  "search": { "id": "uuid", "status": "queued", "...": "тот же объект, что ответ POST /search-jobs" }
}
```

- `search.id` дальше опрашивается обычным `GET /search-jobs/{id}`, webhook работает как обычно.
- `filters` — что сервер понял из ссылки (любое поле может быть `null`). Нужно GS Home для подписи
  и направления; на поиск не влияет.
- Найденное отдаётся без наших фильтров: выдачу отобрал сайт.
- Кеш 30 минут и «повтор, пока идёт обход» — по нормализованному `source_url`, как сейчас.

### `GET /api/v1/me`

Новое поле `imports`: список сайтов, ссылки с которых сейчас принимаются (`["myhome_ge", "ss_ge"]`).
Нет поля или пустой список — GS Home кнопку не показывает.

## Что решает Real Estate (не GS Home)

- Какие адреса считаются объявлением и выдачей на каждом сайте, включая языковые префиксы
  `/ka/ /en/ /ru/` и мобильные адреса.
- Нормализация: убрать метки (`utm_*`, `fbclid`), номер страницы, приведение к канонической форме.
- Выдача: какие параметры сайта сохраняются как есть. Сохранять нужно все фильтры сайта (их и
  ждёт агент), порядок «свежие первыми» можно навязать. Проверить, что `canonicalUrl` сборщика не
  выбрасывает незнакомые параметры.
- Задание `card` без нашего id: как сборщик примет `cards: [{url}]` и как импорт свяжет итог с
  `imports.id`.
- Лимиты и потолок: новая карточка считается как актуализация (`refresh_busy`), выдача — как поиск.
- (Ответ Real Estate, 29.10.) Тоже 422 в `fields.url`: старый адрес `ss.ge/…` (не `home.ss.ge`) — текст
  просит прислать новую ссылку; выдача myhome с повторяющимися или скобочными параметрами (`a[]=`,
  `a=1&a=2`); ссылка длиннее 1000 символов после нормализации. GS Home пропускает до 2000 — дальше
  решает Real Estate.
- (Ответ Real Estate, 29.10.) Выдача по ссылке делит кеш 30 минут и «повтор, пока идёт обход» с
  `POST /search-jobs`, если её адрес совпадает с тем, что собрал бы фильтр.
- (Ответ Real Estate, 29.10.) Выдача с параметрами, которые сборщик не может сверить с ответом сайта, — 422 с текстом в `fields.url`, а не молча расширенный поиск.

## Выложено (Real Estate, 29.10)

- `POST /imports` всегда отвечает 202, в том числе для объявления, которое уже есть в базе (`status: done`, `listing_id`).
- Если карточку уже обрабатывает другое задание (чужая актуализация), импорт подключается к нему, и `refresh_busy` / `site_paused` не придут.
- Ссылку myhome на ru или en сервер нормализует в `https://www.myhome.ge/pr/<id>/`.
- Окончательный отказ приходит сразу как `failed`. Ждёт только сбой сохранения присланной карточки: было 15 минут; по просьбе владельца Real Estate сокращает окно до 3 минут (выложит отдельно, сообщит).
- Проверено вживую 29.10:
  - объявление из базы открывает карточку (агенту продаж — и арендную, по подписи `link`);
  - новое объявление попадает в колокольчик примерно через 2,5 минуты;
  - выдача ss.ge становится поиском (80 найдено, `utm_*` отрезан).

## Что не делаем

- Не дополняем выдачу по ссылке нашими фильтрами и не пытаемся перевести её в форму «Найти квартиру».
- Ссылки на другие сайты (не myhome и не ss.ge) не принимаем.
