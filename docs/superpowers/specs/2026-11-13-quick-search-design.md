# Главная и быстрый поиск — дизайн

Дата: 2026-11-13. Связано: `~/Sites/real-estate.devstudio.ge/docs/superpowers/specs/2026-11-13-site-search-filters-design.md`
(адрес выдачи по любым фильтрам). Модуль поиска — [[12_Поиск_на_сайтах]].

## Зачем

Клиент хочет на телефоне за несколько касаний найти квартиру по цене, площади и числу спален, как на
myhome.ge. Сейчас главная показывает виджеты Filament (профиль, «Filament info») и ленту CRM, а поиск спрятан
в окне «Найти квартиру» — длинная форма, неудобная на телефоне.

## Цели, не цели, анти-цели

Цели:
- главная: всё прежнее скрыто; на ней — быстрый поиск и последние поиски;
- быстрый поиск: сделка, тип, место, «Цена», «Площадь», «Спальни» и переключатель режима:
  **«Свежий»** — поиск на сайтах (myhome + ss.ge через сборщика, 1–3 мин; вариант Б, решение пользователя 13.11,
  режим по умолчанию) и **«По базе»** — сразу, по уже собранным объявлениям (экран «Объекты» с этими фильтрами;
  добавлено пользователем 13.11);
- если сборщиков нет на связи — строка говорит об этом и предлагает «По базе»;
- та же строка над «Объектами»;
- в первую очередь телефон (375 px), на компьютере — в одну строку.

Не цели: менять окно «Найти квартиру» и «По ссылке» (остаются как есть); комнаты в быстром поиске (они в полной
форме).

Анти-цели: каждое касание фильтра запускает поиск (лимит 60 в час на всех); человек не понимает, что поиск идёт
1–3 минуты; поиск, который заведомо пропустит ss.ge, без предупреждения.

## Подходы

1. **Новая строка быстрого поиска под телефон (выбрано пользователем).** Кнопки-фильтры, панели снизу на
   телефоне, выпадающие окна на компьютере; запуск через уже готовый `SiteSearches::start`.
2. Перерисовать окно «Найти квартиру» и открывать его с главной — длинная форма в окне на телефоне. Отклонено.
3. Собирать ссылку myhome в GS Home и слать через «По ссылке» — только один сайт, дублирует Real Estate. Отклонено.

## Как выглядит (телефон)

```
┌───────────────────────────────┐
│ Найти квартиру                │
│ [● Свежий  |  По базе ]       │  ← режим; подпись под кнопкой меняется
│ [● Продажа | Аренда ]         │  ← только если у человека оба направления
│ [🏠 Квартира            ▾]    │
│ [📍 Тбилиси · Ваке, Сабу… ]   │  ← панель с поиском города/района/подрайона
│ (до $90 000)(Площадь)(2 сп.)  │  ← заполненная кнопка показывает значение
│ [   🔍 Искать на сайтах    ]  │  ← «По базе»: [🔍 Показать]
│   myhome.ge и ss.ge · 1–3 мин │  ← «По базе»: «сразу, уже собранное»
│ ⚠ Сборщики не на связи —      │  ← только когда refresh_sources пуст
│   свежий поиск может не пройти│
│   [Искать по базе]            │
├───────────────────────────────┤
│ Последние поиски              │
│ ◌ Ваке · 2 сп.       ищем…    │
│ ✓ Сабуртало · до $90к  48  →  │
└───────────────────────────────┘
```

Панели: «Цена, $» — от/до и быстрые суммы по сделке (продажа: до 50/100/150 тыс.; аренда: до 500/800/1200);
«Площадь, м²» — от/до и быстрые диапазоны; «Спальни» — 1 2 3 4 5+, несколько. «Сбросить» и «Готово».

## Устройство

- **Главная.** Своя `App\Filament\Pages\Dashboard` (наследник Filament `Dashboard`), без виджетов:
  `AccountWidget`, `FilamentInfoWidget` убираются из панели, `CrmFeed` не показывается на главной (класс
  остаётся — скрыть, не удалять). Содержимое — `QuickSearch` и `RecentSearches`.
- **`App\Livewire\QuickSearch`.** Состояние: `deal`, `property_type_id`, `city_id`, `district_id[]`,
  `subdistrict_id[]`, `price_usd_min/max`, `area_min/max`, `bedrooms[]`. Справочники и поиск места —
  `DictionaryOptions` (как в `FindListing`). Сделка по умолчанию — направление человека
  (`FindListing::normalizeDeal`), тип — «Квартира», город — Тбилиси. Последние значения помнятся в сессии.
  Кнопка → `SiteSearches::start($user, $data)` → `MySearches::notifyStart()`; ошибки — как в `FindListing::runSearch`.
  Права — на сервере, как сейчас.
- **Спальни в теле поиска.** `SiteSearchRequest::build` принимает `bedrooms[]` и шлёт `bedrooms` /
  `bedrooms_min` по тому же правилу «5+», что `rooms`. API Real Estate их уже принимает (отсев у себя); после
  изменения Real Estate они же уйдут в адрес сайта — GS Home ничего не меняет.
- **Режим.** `mode`: `fresh` (по умолчанию) | `base`; последний выбор помнится в сессии. `base` → редирект на
  «Объекты» с `FindListing::baseFilters($data)` + спальни; доступен, только если сделка в своих направлениях
  (`FindListing::inOwnDirections`), иначе переключатель «По базе» неактивен с подсказкой, как в окне «Найти квартиру».
  Лимит 60 в час режим `base` не тратит.
- **Спальни на «Объектах».** Экран «Объекты» получает фильтр спален: `ListingQuery` переводит `bedrooms` в параметр
  API `bedrooms` (`2,3`, `5+`), в панели фильтров — множественный выбор 1–5+, как комнаты. Без этого режим «По базе»
  потерял бы спальни.
- **Сборщики на связи.** `RealEstateClient::me()` уже читается (кнопка «По ссылке», кеш 10 мин); для строки нужен
  свежий ответ: `refresh_sources` с кешем 1 мин. Пусто — предупреждение и кнопка «Искать по базе» (переключает
  режим). Сбой `/me` — предупреждения нет, поиск не блокируется.
- **Предупреждение про ss.ge.** Без типа или без города/района ss.ge пропустится: под кнопкой — серая строка
  «ss.ge не ищет без …». Поиск не запрещаем: myhome отработает.
- **`App\Livewire\RecentSearches`.** Три последних `ListingSearch` человека (`scopeVisibleTo` не нужен — только
  свои): подпись `FiltersSummary`, статус, число `shown()`, ссылка на экран результата. `wire:poll.10s`, только
  пока есть идущий поиск.
- **«Объекты».** Над списком — та же `QuickSearch` в свёрнутом виде: одна строка-сводка («🔍 Ваке · Квартира ·
  до $90к»), по нажатию раскрывается. Панель фильтров базы ниже не меняется.
- **Вёрстка.** Tailwind 4 и токены панели (основной цвет — тёмно-синий агентства). Кнопки-фильтры
  `rounded-full`, касание не меньше 44 px; панели — снизу экрана до `sm`, выпадающие от `sm`; на `md+` поля
  в одну строку. Отступы под safe area. Alpine для открытия панелей, Livewire — только на «Готово» и «Искать»
  (не гонять запрос на каждое число). Тёмная тема — как вся панель.
- **Подписи** — `lang/{ru,en,ka}/gshome.php`, ключи `quick_search.*`.

## Проверка

- Тесты: режим `base` → редирект на «Объекты» с фильтрами, включая спальни, и без POST в Real Estate; `base` с чужим
  направлением недоступен; пустой `refresh_sources` → предупреждение видно; главная без виджетов; `QuickSearch` запускает поиск с ожидаемым телом (`Http::fake`), «5+» спален →
  `bedrooms_min: 5`; чужое направление → 403; пустая форма (нет ни места, ни типа, ни цены) — кнопка неактивна.
- Вёрстка — `visual-audit` на 375/768/1280 для главной и «Объектов»; мобильный Safari — iOS Simulator
  (панели снизу, клавиатура над полем «от/до»).

## Решено

- Переключатель «Свежий / По базе» — пользователь, 13.11 (подписи «Свежий» и «По базе» — предложение агента вместо
  «по старым данным»: в базе есть и свежие объявления). Предупреждение о сборщиках — по замечанию второго агента.
- Вариант Б (сайты по умолчанию), строка как на myhome, спальни вместо комнат — пользователь, 13.11.
- Последние поиски на главной, свёрнутая строка над «Объектами», подсказки сумм по сделке, только USD, умолчания
  «Квартира»/Тбилиси, память значений в сессии — предложения агента, пользователь не возражал (13.11).

## На усмотрение исполнителя

Разбиение на Blade-компоненты, точные быстрые суммы, иконки.
