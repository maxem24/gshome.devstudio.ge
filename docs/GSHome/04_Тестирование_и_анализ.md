# Тестирование и анализ

## TL;DR

| проверка | команда | время | когда |
|---|---|---|---|
| PHPStan | `docker compose exec app composer analyse` | секунды | после каждой пачки правок |
| точечный тест | `docker compose run --rm test php artisan test --filter <имя>` | секунды | после правки логики |
| быстрые ворота | `bin/ship.sh --quick` | ~10 с | по ходу работы |
| полный сьют | `docker compose run --rm test composer test` | — | один раз перед PR (входит в `bin/ship.sh`) |
| инспекции IDE | `mcp__phpstorm__get_file_problems` | — | по каждому изменённому файлу перед сдачей |

PHPStan в разы быстрее сьюта и ловит то, куда тесты не заходят: опечатку в
имени метода, несовпадение типа, недостижимую ветку. Гонять его наравне с
проверкой синтаксиса, а не «перед сдачей».

## Тесты

- **Только в сервисе `test`.** У `app` в окружении `DB_DATABASE=gshome`, а
  переменные окружения сильнее `<env>` в `phpunit.xml`.
- **База — `gshome_test`** (создаётся при первом старте тома, `docker/postgres/init`).
  `composer test` идёт параллельно (paratest), Laravel сам заводит
  `gshome_test_test_N` на каждый процесс.
- **Три слоя защиты рабочей базы:** `force="true"` и `<server>` в `phpunit.xml`
  (Laravel читает `$_SERVER` раньше `$_ENV`); `TestCase` отвергает базу без `_test`
  и закешированный конфиг — до `parent::setUp()`, потому что `RefreshDatabase`
  стирает базу внутри него.
- **Тесты не ходят в сеть:** `Http::preventStrayRequests()` в `TestCase`. API Real
  Estate в тестах — только через `Http::fake()`.
- Xdebug в тестах выключен (`XDEBUG_MODE=off` в `phpunit.xml`): с ним PHP в 5–10 раз медленнее.
- `executionOrder="defects"`: упавшие в прошлый раз тесты идут первыми.
- Падающий тест сначала проверить на «был ли красным до моей правки»: `git stash`,
  прогон с `--filter`, `git stash pop`.
- `composer test:sequential` — для отладки (параллельный режим прячет `dump()`).

## PHPStan (Larastan)

`phpstan.neon`: уровень 5, `treatPhpDocTypesAsCertain: false` и
`parseModelCastsMethod: true` — как в BigMed. Baseline нет: проект начат с чистого
анализа, и так должно остаться (`composer analyse:baseline` — только осознанно).

Анализатору верят после самопроверки: `bin/preflight.sh` и CI подсовывают файл с
тремя заведомыми ошибками и ждут хотя бы две. Молчание сломанного инструмента
выглядит так же, как чистый код.

## Стиль

- **Pint** — PHP. Проект начат с чистого Pint, поэтому `bin/ship.sh` проверяет
  изменённые файлы и блокирует. Исправить: `docker compose exec app vendor/bin/pint --dirty`.
- **Prettier** (`.prettierrc` из BigMed: blade + tailwind плагины, 4 пробела, ширина 100) —
  blade, js, css, json. Исправить: `docker compose run --rm node npx prettier --write <файл>`.
- `git diff --check` — пробелы в добавленных строках.

## CI (`.github/workflows/static-analysis.yml`)

На push и PR в `main`: PHPStan с самопроверкой и сверка `package-lock.json` с
`package.json` на Node 24. Сьюта в CI пока нет — как в BigMed.
