# Поиск на сайтах: где что и что нельзя сломать

Спецификация — `docs/superpowers/specs/2026-10-27-site-search-design.md`, план —
`docs/superpowers/plans/2026-10-27-site-search.md`. Решения от 27.10 — в [[02_Решения]].

Что делает модуль: агент в любом месте админки жмёт «Найти квартиру», задаёт фильтры и либо смотрит
базу Real Estate, либо ставит поиск на myhome.ge и ss.ge. Поиск идёт в фоне через сборщика (компьютер
агента), результат приходит в колокольчик. GS Home своих объявлений не ведёт: карточки читаются живыми
по id из API Real Estate.

## Правила, которые легко сломать

- **POST не повторяем.** `startSearch()` идёт с `retry(1, …)`: повтор после принятого задания создаёт
  дубль и съедает лимит 60 в час. Опрос (`searchStatus`, GET) повторяется обычной политикой клиента.
- **Замок вокруг старта.** `SiteSearches::start()` берёт `pg_advisory_xact_lock` по id человека и
  хэшу тела и делает POST внутри той же транзакции. Два одновременных старта с теми же фильтрами шлют
  один POST. Не выносить POST из транзакции ради «быстрее»: замок тогда не работает.
- **Повтор не ставит второй поиск.** Того же человека с теми же фильтрами: если идущий поиск моложе
  `timeout_minutes`, возвращается он; если готовый — моложе `reuse_minutes`, возвращается он без
  запроса к Real Estate. Старше идущий поиск закрывается как `timed_out` и не блокирует повтор.
- **Уведомление — один раз.** `SiteSearches::finish()` ставит `notified_at` под `lockForUpdate`;
  сколько раз ни позови (опрос, `close`, `refresh`), колокольчик получит одно сообщение.
- **Поздний `timed_out` не затирает `done`.** `whileRunning()` меняет строку только пока она идёт.
- **Упавший опрос не оставляет «в работе».** `PollListingSearch::failed()` закрывает поиск как `failed`
  и уведомляет. `tries = 1`: повтора задачи нет, каждый шаг ставит следующий опрос сам.
- **404 на опросе — «потерян», не сбой.** Чужой или стёртый на стороне Real Estate id даёт
  `RealEstateSearchNotFound`; `refresh()` ставит `failed` со словами «потерян».
- **`isPartial()` не считает `skipped`.** Сайт, который не подошёл под фильтры, — не сбой; частичным
  поиск делают только сайты в статусе, отличном от `done` и `skipped`.
- **Права на сервере, не в форме.** Сделка по умолчанию — из `OrgAccess::directions`, но искать можно и
  в другом направлении (скрытая опция формы, [[02_Решения]], 27.10); `CrmForbidden` — только для неизвестной
  сделки или человека без направлений. Это отступление касается только поиска на сайтах: экран «Объекты» не
  меняется. Чужой поиск в списке и на экране результата не виден:
  `ListingSearch::scopeVisibleTo()` строится на `OrgAccess::visibleUsers()`.
- **Карточки — только направления самого поиска.** `SearchResult::fetchRows()` берёт направления из
  `ListingSearch::directions()` (сделка из фильтров, иначе направления автора) и отбрасывает остальные
  и снятые объявления; снятые считаются в `hidden`. Ошибка чтения не значит «скрыто»:
  вместо этого — предупреждение о неполном списке.
- **«Показать в базе» передаёт район, только если он один.** Экран «Объекты» знает один район и не
  знает подрайонов (см. [[02_Решения]], 27.10).
- **Журнал без личных данных.** `search.started` и `search.finished` пишутся с пустыми свойствами
  (старт) или статусом и числом найденного (финиш). Фильтров и имён в журнале нет; в ленту события не
  попадают.
- **Не копируем карточки.** В `listing_searches` лежат только `listing_ids` и `sites`. Сами объявления
  читаются из Real Estate при открытии результата.
- **Направление — через `OrgAccess`.** Новые проверки «кто что видит» — в `OrgAccess`, не в экране.

## Ограничения

- **Лимит 60 поисков в час на ключ GS Home.** Один ключ на всех агентов. Лимитер `api-search-jobs` стоит
  на маршруте Real Estate и считает каждый POST, даже ответ из кеша Real Estate. Поэтому повтор внутри
  GS Home сначала проверяем у себя. Поднять лимит — `api_clients.search_jobs_per_hour` в Real Estate.
- **Сборщики — компьютеры агентов.** Если ни один не на связи, поиск висит до 30 минут и заканчивается
  «Не дождались сборщиков». Это не сбой GS Home.
- **Нет отмены поиска:** в API Real Estate её нет.
- **Не автоматический поиск при каждом изменении фильтра** — иначе лимит уйдёт за минуты.
- **Результат появляется через 1–3 минуты** и только в колокольчике; push на телефон нет.
- **Что сказать после старта.** `SiteSearches::start()` возвращает `App\Search\SearchStart` (`search`,
  `kind`): `new` — «Поиск запущен…», `running` — «Такой поиск уже идёт…», `reused` — «Есть свежий
  результат» со ссылкой на экран результата (колокольчика в этом случае не будет). Тексты ставит
  `MySearches::notifyStart()`, его зовут окно поиска и «Искать снова».
- **Два числа.** `found` — сколько номеров нашли сайты до наших фильтров; `listing_ids` — что прошло
  фильтры (до 100). Главное число (колокольчик, список, экран результата) — `ListingSearch::shown()`,
  то есть `count(listing_ids)`; `found` — вторая строка «Найдено на сайтах: N» (+ «показаны 100 самых
  свежих», если выдача обрезана).
- **Комнаты «5+».** API строку «5+» не принимает. Одна «5+» уходит как `rooms_min: 5`; вместе с другими
  значениями — `rooms: [другие…, 5, 6, 7, 8, 9, 10]` (`SiteSearchRequest::rooms()`).
- **422 `validation_failed` на старте** — `RealEstateSearchRejected`: сайты не приняли фильтры
  (например, район без соответствия). Это предупреждение в лог, не ошибка; человеку — «Этот район не
  поддерживается сайтами» или общий отказ. Окно остаётся открытым.
- **401/403 на опросе** — поиск сразу закрывается как `failed` («Доступ к Real Estate закрыт…»), а не
  ждёт 30 минут.
- **Язык.** Опрос просит у API `lang` владельца поиска; сообщение `failed()` и уведомление — на языке
  владельца (`users.locale`).

## Отложено: вставка ссылки ss.ge / myhome

Импорт объявления по ссылке в GS Home пока не сделан. Нужен новый API в Real Estate: задание `card`
сборщику уже умеет читать карточку, но API, который его ставит, ещё не написан. Работа — на стороне
Real Estate, потом поле ссылки здесь. Решение — в [[02_Решения]], 27.10.

## Команды

`php artisan search:sweep` (расписание: каждые 5 минут, `routes/console.php`; нужен сервис `scheduler`)
закрывает как `timed_out` поиски, которые «идут» дольше `timeout_minutes`: опрос мог пропасть вместе с
очередью (рестарт Horizon, потеря задания). Закрытие идёт через `SiteSearches::close()`, уведомление
приходит один раз. Если после `PollListingSearch::dispatch` очередь недоступна, `start()` не отдаёт 500, а
закрывает поиск как `failed`. Сам опрос идёт в очереди Horizon.

    docker compose restart horizon     # после правки джоб: Horizon держит код в памяти
    docker compose run --rm test php artisan test --filter SiteSearches   # точечные тесты поиска (см. 04_Тестирование_и_анализ)

Настройки меняются в `config/search.php`; ключ лимита живёт в Real Estate, не здесь.

## «Собрать полную информацию» по объявлению

С 27.10.2026. Кнопка на карточке объявления (`ListingView`, действие `collectFullInfo`). Real Estate ставит
сборщикам задания `card` на каждый сайт группы, открывает карточку объявления и всех его дублей и отдаёт полную
свежую версию: комнаты, телефон, фото, снято или нет. API — `~/Sites/real-estate.devstudio.ge/docs/RealEstate/16_API_актуализация.md`
(`POST /listings/{id}/refresh`, `GET /listing-refreshes/{id}`).

- **Когда видна:** у объявления `refreshable = true` (есть сборщик на связи и хотя бы один сайт группы не на паузе;
  меняется со временем, читается с карточкой — кеш 60 с) и сейчас ничего не собирается. Право — то же, что открыть
  карточку.
- **Ожидание:** опрос из браузера (`wire:poll`, шаг `poll_after_ms`), без таблицы и колокольчика. Плашка «Собираем
  данные с сайтов, обычно до N мин» со списком копий. Срок у Real Estate — 10 минут (`deadline_at`); через срок
  + 15 с перестаём ждать. Ушёл со страницы — не страшно: данные сохранятся у Real Estate, следующий показ их возьмёт.
- **Итог:** кеш карточки сбрасывается на всех языках, карточка пересобирается из `data.listing` без нового запроса.
  Цена изменилась — «Цена изменилась: было X». `listing.status = inactive` — крупно «Объявление снято с
  публикации <дата>», карточка остаётся прежней. По сайтам одной строкой: «ss.ge — обновлено; myhome.ge — <`error`
  из API как есть>». `stale` — «Не все сайты ответили, данные на <дата>».
- **Ошибки:** 503 `refresh_busy` — «Сервис занят, попробуйте через полминуты»; 429 — как везде; POST без повторов.
  Повторное нажатие, пока идёт прошлое, Real Estate отдаёт ту же актуализацию.
- **Итоги у копий** (`items[].outcome`) — ровно `pending`, `refreshed` (скачали заново; «без изменений» сюда же),
  `recent` (открывали меньше 10 минут назад), `removed`, `failed` (причина — готовым текстом в `items[].error`,
  пауза сайта — `paused_until`). Неизвестное значение читаем как `failed`.
- **Журнал:** `listing.refresh_started` (в ленту не идёт).
- **Склейка:** если карточка показала, что копия — другая квартира, группа (`cluster.id`) пересоберётся у Real Estate
  позже плановой пересборкой. Закрепление ищется и по группе, и по id объявления (`Pins::activeFor`) — не потеряется.
- **Пока нет у Real Estate:** фоновое дособирание объявлений `partial: true` без нажатия.

Код: `App\RealEstate\{ListingRefresh, ListingRefreshItem}`, `RealEstateClient::startRefresh/refreshState/forgetCard`,
план — `docs/superpowers/plans/2026-10-27-listing-full-info.md`.
