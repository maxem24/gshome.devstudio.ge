# Договор с собственником и отчёт по договорам — дизайн

Дата: 2026-11-25. Статус: на согласовании.

## Зачем

Агентство ведёт работу с собственниками в ручных журналах (пример — журнал агента
`lkhub64`, ~1000 записей за март–октябрь 2026). Агент находит объявление собственника,
дозванивается, договаривается о цене и комиссии и выкладывает квартиру от агентства на
MyHome и SS.GE. Руководитель хочет видеть эту работу в системе и строить по ней отчёты.

В системе сейчас есть только «Взять в работу» (закрепление объявления за агентом) и
«Предпочтения собственника» (кому готов сдать). Самой договорённости — цены и комиссии —
нет. Отчёт руководителя (`App\Crm\AgentReport`) считает только сторону клиента.

**Успех:** агент после звонка собственнику за полминуты вносит договор; руководитель за
период видит по каждому агенту, сколько договоров, на каких условиях, сколько из них
сдано нами, и ожидаемую комиссию. Директору это показывают на компании `Demo`.

**Анти-цели:** не повторять кашу журнала (свободный текст в колонке комиссии, район 99
написаниями, `$` пометкой); не добавлять агенту шагов и переключателей сверх нужного;
не заставлять вводить то, что система уже знает из объявления.

## Что значат колонки журнала (со слов владельца проекта, 25.11)

| колонка | смысл | в системе |
|---|---|---|
| თარიღი | дата записи | дата договора, ставится сама |
| MYHOME / SS.GE | ID **наших** объявлений агентства на сайтах | два необязательных поля |
| მეპატრონის ID | ID объявления собственника | объявление, взятое в работу (`listing_pins.listing_id`) |
| მეპატრონის ნომ | телефон собственника | из объявления |
| მისამართი | адрес | из объявления |
| зелёная колонка | цена, за которую агент договорился сдавать | **вводит агент** |
| მეპ თანხა | цена, которую хотел собственник | цена объявления собственника, подставляется сама |
| თანამშრომლობა | комиссия агентства с собственника | **выпадающий список** |
| последняя (с апреля) | район | из объявления (`subdistrict_id` снимка) |

Разбор колонки комиссии (журнал `lkhub64`): 50% — 716, 100% — 347, пусто — 321, «?» — 302,
70% — 42, 30% — 17, фиксированная сумма в лари — ~28, «fake» — 14, единично 60%,
«6 мес. 50%», опечатка 1000%. Пусто и «?» — ещё не договорились. «fake» — не комиссия,
а исход работы с объектом. В заметках встречаются «освобождается 7 августа», «только на
6 месяцев», «только иностранцам», «გაქირავდა» (сдана).

## Подходы (рассмотрены 25.11)

- **А. Поля на объекте в работе (`listing_pins`), отдельная кнопка — выбран.** Владелец
  проекта уточнил: форма **не** открывается сама при «Взять в работу». Агент берёт объект,
  а когда дозвонился собственнику (часто на следующий день), нажимает кнопку договора.
  Кнопка — нынешние «Предпочтения собственника», переименованные и дополненные.
  Обычные колонки — отчёты считаются простым SQL.
- Б. Отдельная сущность «договорённость» с версиями — гибче при пересогласованиях, но
  тяжелее в интерфейсе и отчётах. Сейчас не нужна: история правок есть в журнале.
- В. Экран-таблица как журнал — повторяет кашу и дублирует данные объявления. Отклонено.

## Решения владельца проекта

1. Кнопка «Предпочтения собственника» становится кнопкой договора: «Добавить договор»,
   пока договора нет; «Договор с собственником», когда он заполнен. Одно окно: договор +
   нынешние предпочтения («кому готов сдать»).
2. Комиссия — выпадающий список из того, что есть в журнале. Если директору не подойдёт,
   он даст подробности, список переделаем. Остальные пункты добавляются по ходу работы.
3. **Аренда:** 100% месячной аренды · 50% · 70% · 30% · фиксированная сумма ·
   % в течение N месяцев · другое.
4. **Продажа:** 1% · 2% · 3% от цены продажи · фиксированная сумма · другое.
5. Меньше кнопок и выборов, но без ограничения гибкости: для редких случаев есть «другое».

## Дизайн

### Окно «Договор с собственником»

```
Договор с собственником
────────────────────────────────────────
Цена собственника      950 ₾  ($352)      (из объявления, только чтение)
Договорились сдавать   [ 900 ] [₾ | $]
Комиссия               [ 50% месячной аренды      ▾]
   фиксированная  →    [ 300 ] (в валюте цены)
   % × N месяцев  →    [ 50 ] % × [ 6 ] мес.
   другое         →    [ текст до 100 символов ]
Свободна с             [ дата ]           необязательно (только аренда)
Минимальный срок       [ — ▾ ] 6 мес. / 1 год   необязательно (только аренда)
Наши объявления        MyHome [ ID ]   SS.GE [ ID ]   необязательно
── Кому готов сдать ──  нынешние поля предпочтений (только аренда, как сейчас)
Заметка                [ текст ]
────────────────────────────────────────
                                   [ Сохранить ]
```

- Обязательны «Договорились» и «Комиссия»; остальное — по желанию.
- Валюта: по умолчанию ₾ для аренды, $ для продажи; агент может переключить.
- Цена собственника берётся из объявления в выбранной валюте (`priceGel` / `priceUsd`) и
  **сохраняется снимком** при первом сохранении договора: цена в объявлении потом может
  меняться, а скидка в отчёте должна считаться от цены на момент договора.
- ID наших объявлений — только цифры; проверка формата, без проверки существования.
- Дата договора (`agreed_at`) ставится при первом сохранении и при правке не меняется.
- Правка договора доступна тому же, кто сейчас правит предпочтения (`Pins::canManage`),
  пишется в журнал (`pin.agreement_saved`).
- Удалить договор отдельной кнопкой нельзя; объект закрывается как сейчас.

### Карточка объекта

Под кнопками — строка-сводка, видна всем, кто видит объект:
«Договор 12.11: 900 ₾ (собств. 950) · 50% · свободна с 07.08 · MyHome 20639604».
Пока договора нет: «Договора нет — взят в работу 11.11».

### «Объект недоступен» — причина

В подтверждение «Объект недоступен» добавляется одно поле-выбор (необязательное):
«Сдан / продан не нами», «Не собственник (fake)», «Собственник передумал», «Другое».
Хранится в `listing_pins.unavailable_reason`. Нужно отчёту (доля fake, потери).

### Хранение

Новые колонки `listing_pins` (все nullable):

| колонка | тип | смысл |
|---|---|---|
| `agreed_at` | timestamptz | дата договора; NULL — договора нет |
| `agreed_by` | FK users | кто внёс договор (ему засчитывается) |
| `agreed_price` | numeric(12,2) | цена, о которой договорились |
| `agreed_currency` | `GEL`/`USD` | валюта цены и фиксированной комиссии |
| `owner_price` | numeric(12,2) | цена собственника на момент договора, в той же валюте |
| `commission_kind` | `percent` / `fixed` / `percent_months` / `other` | вид комиссии |
| `commission_percent` | smallint | процент (100/50/70/30 или 1/2/3; для `percent_months` — любой 1–100) |
| `commission_months` | smallint | N месяцев для `percent_months` |
| `commission_amount` | numeric(12,2) | сумма для `fixed` |
| `commission_note` | varchar(100) | текст для `other` |
| `available_from` | date | свободна с |
| `min_term_months` | smallint | 6 / 12 |
| `myhome_id`, `ss_id` | bigint | наши объявления |
| `agreement_note` | text | заметка |
| `unavailable_reason` | varchar | причина «недоступен» |

CHECK в базе: договор целиком или никак (`agreed_at`, `agreed_price`, `agreed_currency`,
`commission_kind` — все NULL или все заданы); поля комиссии соответствуют виду; проценты
1–100. Пункт выпадающего списка — это пара (вид, процент): «50%» = `percent` + 50.

Список пунктов задаётся в коде (enum `CommissionOption`) отдельно для аренды и продажи,
чтобы добавить пункт было одной строкой.

### Ожидаемая комиссия (для отчёта)

| вид | аренда | продажа |
|---|---|---|
| `percent` | цена × % | цена × % |
| `fixed` | сумма | сумма |
| `percent_months` | цена × % × N | — |
| `other` | не считается, показывается «другое: N шт.» | так же |

Суммы — по валютам отдельно, как «заработок» в нынешнем отчёте (без конвертации).

### Отчёт руководителя — раздел «Работа с собственниками»

Та же страница `AgentReportPage`, те же правила видимости (`OrgAccess::visibleUsers`),
тот же период. Новая таблица под нынешней, строка на сотрудника:

| показатель | откуда |
|---|---|
| взято в работу | закрепления, `created_at` в периоде |
| договоров | `agreed_at` в периоде |
| без договора дольше N дней | активные закрепления без `agreed_at`, старше `crm.stale_days` |
| условия | разбивка: 100% · 50% · 70% · 30% · фикс · N мес. · другое (продажа: 1/2/3%) |
| средняя скидка от цены собственника | `1 − agreed_price / owner_price`, по договорам периода |
| ожидаемая комиссия | формула выше, по валютам |
| сдано / продано нами | закрепления с договором, закрытые `won` в периоде |
| недоступно | по причинам: не нами · fake · передумал · другое |
| дней до договора / до сдачи | медиана `agreed_at − created_at`, `closed_at − agreed_at` |

Под таблицей — разбивка по районам (`subdistrict_id` снимка): договоров, средняя цена,
средняя скидка. Тенденция по неделям — **не в этой итерации** (см. «Позже»).

### Демо-данные для показа директору

Команда `gshome:owner-agreement-demo` наполняет компанию `Demo` (тимлид и агент аренды
уже заведены на проде 25.11): ~60 закреплений за последние 8 недель на реальных
объявлениях аренды из Real Estate, у ~45 — договор с распределением комиссий как в
журнале (50% ≈ 45%, 100% ≈ 25%, 70%, 30%, фикс, «6 мес. 50%», другое), часть сдана нами
(сделка `won`), часть недоступна по разным причинам, часть без договора. Как и
`CrmDemo`: прошлое через `Carbon::setTestNow`, свои записи запоминает в
`crm_settings['owner_agreement_demo']` и удаляет только их при `--fresh`. Работает
только с компанией `Demo`, иначе отказывается.

## Уточнения после проверки (решения исполнителя дизайна, 25.11)

1. **Предпочтения без договора сохранять можно.** В окне «Договорились» и «Комиссия»
   обязательны только вместе: заполнено одно — нужно и второе; не заполнено ни одно —
   сохраняются только предпочтения и заметка, договора нет, кнопка остаётся «Добавить
   договор». Так не теряется нынешняя возможность записать «кому готов сдать» до цены.
2. **Только активное закрепление.** Вносить и править договор можно, пока объект в работе
   (как сейчас `assertCanManage`). Демо-команда пишет закрытые закрепления с договором
   напрямую, минуя сервис.
3. **Договор засчитывается тому, кто его внёс.** Новая колонка `agreed_by` (FK users).
   «Договоров», условия, скидка и ожидаемая комиссия в отчёте — по `agreed_by`;
   «взято в работу» — по создателю закрепления (`user_id` на момент взятия, т. е. если
   передачи не было; при передаче — текущий держатель, как в нынешнем отчёте);
   «сдано нами», «недоступно», «без договора» — по текущему держателю.
4. **Цена собственника** — `priceGel` или `priceUsd` объявления в выбранной валюте. Нет
   цены в этой валюте — `owner_price` NULL, в CHECK «договор целиком» не входит, средняя
   скидка такие договоры пропускает.
5. **Один раздел отчёта, строка на сотрудника.** Колонка «условия» показывает пункты того
   направления, в котором договор (аренда: 100/50/70/30/фикс/N мес./другое; продажа:
   1/2/3%/фикс/другое) — подписи пунктов однозначны, смешивать не страшно. Ожидаемая
   комиссия — по валютам; скидка — средняя по всем договорам сотрудника.
6. **«Сдано / продано нами»** — закрепление с договором, закрытое с `closed_reason='won'`
   в периоде; без договора в показатель не идёт. «Дней до сдачи» — `pin.closed_at − agreed_at`.
7. **Период** — по событиям, без когорт: «взято» по `created_at`, «договоров» по
   `agreed_at`, «сдано» по `closed_at`. Отдельная колонка «договоров / взято, %» не нужна:
   при разных периодах событий она вводит в заблуждение.
8. **Группировка условий**: `percent` — по проценту; `percent_months` — одной группой
   «N мес.»; `fixed` — «фикс»; `other` — «другое».
9. **Причина «недоступен»** необязательна; закрытые без причины (включая старые) — в
   отчёте отдельной категорией «не указана».

## Ограничения

- PHP 8.5, Laravel 13, Filament 5, PostgreSQL; инварианты — CHECK в базе.
- Права — только через `Pins::canManage` / `OrgAccess`, новых правил видимости нет.
- Переводы ka / ru / en (`lang/*/gshome.php`).
- Тесты PHPUnit на: сохранение договора (права, CHECK, снимок цены, `agreed_at` не
  меняется), формулу ожидаемой комиссии, отчёт (агрегаты на фикстурах), демо-команду
  (только `Demo`, `--fresh` удаляет только своё).

## Не в этой итерации («Позже»)

- Автопоиск наших объявлений на MyHome / SS.GE по группе дублей и телефону компании.
- Тенденция по неделям / графики.
- Договор с собственником как документ (файл, подпись, эксклюзив).
- Учёт фактически полученной комиссии с собственника (сейчас — ожидаемая).

## Оставлено исполнителю

Раскладка окна и сводки в Filament, тексты переводов, точные имена событий журнала,
индексы под отчёт.
