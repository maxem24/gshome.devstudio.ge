# API: кнопка «Актуализировать»

**Соседи:** [[16_API]] · [[04_Скрейпинг_и_очереди]]

Документ для разработчика системы-клиента (GS Home и другие), который делает кнопку
«Актуализировать данные» в карточке объявления. Подключение, ключ, формат карточки и общие ошибки —
в [[16_API]]. Дизайн и решения — `docs/superpowers/specs/2026-10-13-listing-refresh-design.md`.

---

## Зачем

Наши данные отстают от сайтов-источников. Снятое владельцем объявление («продано») мы замечаем
только ночным обходом — до двух суток. Перед звонком агент нажимает «Актуализировать»: мы вне
очереди перескачиваем объявление **и все его дубли со всех сайтов** (ss.ge, myhome.ge…),
сохраняем у себя и отдаём свежую версию. Так агент не предлагает клиенту квартиру, которой уже нет
в продаже.

## Как это работает

Асинхронно: запуск сразу отвечает, а результат клиент забирает опросом.

```
агент жмёт кнопку
  → POST /listings/{id}/refresh            202, id актуализации, eta_seconds
  → карточка заблокирована: «Подождите, обновляем данные (~eta_seconds с)…»
  → каждые poll_after_ms: GET /listing-refreshes/{refresh_id}
        status = queued | running          ждём дальше
        status = done                      показываем data.listing — свежая карточка
        status = stale                     показываем data.listing + «не все сайты ответили» (через 3 мин)
  → карточка разблокирована
```

Ориентир: одно объявление — ~5 секунд, объявление с 10 дублями — ~30 секунд, 30 объявлений —
~1,5 минуты (сайт отдаёт нам не больше страницы в секунду на всё сразу). **Всегда предупреждайте пользователя, что это может занять время**,
и показывайте `eta_seconds`.

## Запуск

`POST /listings/{id}/refresh` — тело не нужно; `?lang=ka|en|ru` как у карточки.

- Можно звать и для снятого объявления (его могли вернуть в продажу).
- Повторное нажатие, пока прошлая актуализация этого объявления не закончилась, вернёт **ту же**
  актуализацию (тот же `id`) — новых запросов к сайтам не будет. Блокировать кнопку на время
  ожидания всё равно стоит.
- Объявления, проверенные у нас меньше 10 минут назад, заново не скачиваются (`outcome: recent`):
  результат приходит сразу.

Ответ **202**:

```json
{
  "data": {
    "id": "9f3c2a1e-7b4d-4c55-9a0e-1d2f3a4b5c6d",
    "status": "queued",
    "listing_id": 123,
    "listings_total": 12,
    "listings_refreshing": 11,
    "truncated": false,
    "paused": false,
    "eta_seconds": 15,
    "poll_after_ms": 2000,
    "created_at": "2026-10-13T20:15:00+04:00",
    "deadline_at": "2026-10-13T20:18:00+04:00",
    "items": [
      {"id": 123, "source": "ss_ge", "source_url": "https://home.ss.ge/…", "status": "active",
       "outcome": "pending", "checked_at": "2026-10-10T09:12:00+04:00", "deactivated_at": null},
      {"id": 456, "source": "myhome_ge", "source_url": "https://www.myhome.ge/…", "status": "active",
       "outcome": "recent", "checked_at": "2026-10-13T20:09:41+04:00", "deactivated_at": null}
    ],
    "listing": null
  }
}
```

| Поле | Смысл |
|---|---|
| `id` | номер актуализации — для опроса |
| `status` | `queued` (ждёт очереди) → `running` (часть уже проверена) → `done` (всё проверено) или `stale` (прошло 3 минуты, не всё проверено) |
| `listings_total` | объявление + все его активные дубли на всех сайтах |
| `listings_refreshing` | сколько скачиваем заново (без проверенных недавно) |
| `truncated` | `true` — обновляются не все дубли: их больше 30 или сервис сейчас загружен (тогда меньше 30). Порядок: само объявление, затем дубли с тем же телефоном, затем самые свежие. Остальные можно актуализировать по их `id` |
| `paused` | сайт-источник временно ограничил наши запросы — ожидание затянется; можно сразу сказать пользователю |
| `eta_seconds` | примерное ожидание; `0`, когда закончено |
| `poll_after_ms` | как часто опрашивать (2000) |
| `items[]` | объявление и дубли: `id`, `source`, `source_url`, `status` (`active`/`inactive`), `outcome`, `checked_at` (когда мы последний раз скачали страницу), `deactivated_at` (когда сняли) |
| `listing` | `null`, пока ждём; при `done`/`stale` — карточка объявления в обычном формате [[16_API]], **включая снятое** |

`outcome` у объявления:

| `outcome` | Что значит | Что показать |
|---|---|---|
| `pending` | ещё не проверено | крутилку |
| `refreshed` | скачали заново, данные свежие | — |
| `recent` | проверяли меньше 10 минут назад, не трогали | — |
| `removed` | на сайте снято с публикации | «Снято с публикации» у этой ссылки |
| `failed` | сайт не отдал страницу (сбой) | «Не удалось проверить, данные на `checked_at`» |

## Опрос

`GET /listing-refreshes/{id}` — тот же формат. Чужую актуализацию (другого ключа/клиента) не видно — 404.
Опрашивайте каждые `poll_after_ms`, пока `status` не станет `done` или `stale`; дольше `deadline_at`
+ несколько секунд не ждите.

## Что показывать пользователю

- **Во время ожидания:** карточка заблокирована, «Подождите, обновляем данные с сайтов (~N с)».
  При `paused: true` — «Сайт временно ограничил запросы, это может занять до 3 минут».
- **`done`, `listing.status = active`:** свежая карточка; можно подсветить изменившуюся цену
  (сравните с тем, что было показано).
- **`done`, `listing.status = inactive`:** крупно «Объявление снято с публикации» и `deactivated_at`.
  Это главный сценарий кнопки: не звонить по проданной квартире.
- **Дубли:** по `items[]` — список «это же объявление на других сайтах»: ссылка `source_url`,
  статус «опубликовано / снято», когда проверено.
- **`stale`:** карточка с пометкой «Не все сайты ответили, данные на <checked_at>».
- **`truncated: true`:** «Показаны не все дубли» — по желанию.

## Ошибки

| HTTP | Когда | Что делать |
|---|---|---|
| 202 | запуск принят (в том числе повторное нажатие) | опрашивать |
| 404 | объявления нет у нас / чужая или неизвестная актуализация | показать ошибку |
| 503 `refresh_busy` | сейчас актуализируется слишком много объявлений (у всех клиентов вместе или у вашего — больше 40 ждут) | ждать `Retry-After` (30 с), сказать «Сервис занят, попробуйте через полминуты» |
| 429 | превышен лимит нажатий клиента (по умолчанию 10 в минуту) или общий лимит API | ждать `Retry-After` секунд; кнопку временно выключить |
| 401/403/5xx | как в [[16_API]] | |

Лимит нажатий — у каждого клиента свой (`refresh_per_minute`, виден в `GET /me`), меняется
администратором в админке «Система → API-клиенты». Опрос `GET /listing-refreshes/{id}` считается
в общий лимит запросов.

## Пример (Laravel, сторона клиента)

```php
$start = $api->post("/listings/{$id}/refresh")->throw()->json('data');
// показать «Подождите (~{$start['eta_seconds']} с)», заблокировать карточку

$deadline = now()->addSeconds(max(130, $start['eta_seconds'] + 30));
do {
    usleep($start['poll_after_ms'] * 1000);
    $state = $api->get("/listing-refreshes/{$start['id']}")->throw()->json('data');
} while (! in_array($state['status'], ['done', 'stale'], true) && now()->lt($deadline));

$card = $state['listing']; // свежая карточка; $card['status'] === 'inactive' — снято
```

В браузере то же самое — `fetch` + `setTimeout`, без держания соединения.

## Для нас

| | |
|---|---|
| Маршруты | `routes/api.php`: `POST listings/{listing}/refresh` (`throttle:api-refresh`), `GET listing-refreshes/{refresh}`; единственная запись в API — тест `ApiRoutesAreReadOnlyTest` |
| Логика | `App\Services\Api\ListingRefreshService` (`start`, `state`, `eta`); ответ — `ListingRefreshResource` |
| Хранение | `listing_refreshes` (uuid, клиент, объявление, `items` = строки `scrape_queue`); чистка — `model:prune` через 7 дней |
| Очередь | `ScrapeListingJob` в `scraping-urgent` (Horizon, supervisor скрапинга, `balance=auto` — у очереди свой воркер); темп — окно источника (`paceQueue`), бюджет сайта общий с обходом; в очереди `found_reason = refresh` |
| Приоритет | пока ждут срочные строки источника (`UrgentRows::waiting`, не старше срока), обычные задачи уступают окна: `PaceScrapeRequests` возвращает их на 5 с, но не больше 3 раз подряд — обход не останавливается совсем. Лишняя задача (строка уже скачана/отменена, `ScrapeListingJob::wanted`) окно не занимает; строка берётся атомарно (`queued` → `processing`) |
| Потолок | срочных строк у всех клиентов — не больше `api.refresh.max_active` (120), у одного клиента — `max_active_per_client` (40), дальше 503 `refresh_busy`; нажатие ставит не больше, чем осталось места под обоими потолками (остальное — `truncated`); проверка и постановка — под замком `listing-refresh:start`; «Стоп» скрапинга чистит и срочную очередь, «Отменить» источника возвращает строки в `pending` — срочная задача их не берёт |
| Настройки | `config/api.php` → `refresh`: `max_listings` 30, `cooldown_minutes` 10, `deadline_seconds` 180, `max_active` 120 (env `API_REFRESH_*`); лимит нажатий — `api_clients.refresh_per_minute` (по умолчанию 10) |
| Известные ограничения | ход пересчитывается по живым строкам: если строку позже возьмёт обычный обход, `done` старой актуализации может снова стать `running`; объявление без строки очереди и без `source_url` сразу `failed`; срочные `queued` уменьшают дозаполнение обычной очереди (`--top-up`) на время ожидания |
| Ход | считается при чтении по строкам очереди: `processed_at` (для `failed` — `updated_at`) не раньше начала актуализации |
