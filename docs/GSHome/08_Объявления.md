# Объявления

Спецификация — `docs/superpowers/specs/2026-10-10-listings-screen-design.md`. Требования к API —
[[07_Требования_к_API_Real_Estate]]. Метки — [[05_Оргструктура]]. Решения — [[02_Решения]].

## Где что

| что | где |
|---|---|
| клиент API, ошибки → исключения, кеш справочников, повторы | `App\RealEstate\RealEstateClient`, `App\RealEstate\Exceptions\*` |
| объявление из ответа API | `App\RealEstate\Listing` (язык с откатом на `ka`, категория продавца, номер E.164, `safeUrl`) |
| параметры запроса, **направление по правам**, лимит телефонов | `App\RealEstate\ListingQuery` (`MAX_PHONES = 500`) |
| строки таблицы, метки страницы, вторая метка группы | `App\RealEstate\ListingRows` (`groupOwnership`), `OrgAccess::ownershipMany` |
| курсор API в таблице Filament | `App\RealEstate\Pagination\ApiCursorPaginator` |
| экраны | `App\Filament\Pages\Listings` (`/admin/listings`, `?display=grid\|list`), `ListingView` (`/admin/listings/{id}`) |

## Правила, которые легко сломать

- Направление в запрос ставит только `ListingQuery` из `OrgAccess::directions()`. Параметр из
  браузера только сужает разрешённое.
- `daily_rent` и `pledge` в GS Home не попадают: список их не запрашивает, карточка отвечает 404.
- Метки страницы — одним вызовом `ownershipMany`; не звать `ownership()` в цикле.
- Вторая метка группы дублей — `ListingRows::groupOwnership(Ownership, Listing, array)`. Номер
  самого объявления в неё не входит.
- Фильтры по телефонам — за `REAL_ESTATE_PHONE_FILTERS`: API отвергает неизвестные параметры (422).
  Больше 500 номеров в фильтре → `TooManyPhones` с понятным текстом, запрос не уходит.
- **Курсор привязан к сортировке.** API отвечает 422 на курсор с другим `sort`. Поэтому Filament
  сбрасывает страницу при смене фильтра или поиска (тест `test_changing_filter_or_search_drops_the_cursor`).
  Не убирать этот сброс.
- **Строки таблицы — массивы, и Laravel переиндексирует их 0..n.** Id объявления — `$record['id']`,
  никогда ключ строки.
- **Переключатель «сетка / список» — параметр адреса `?display=grid|list`**, не `?view=`: `$view`
  занят Filament `Page`. По умолчанию сетка (`$display = 'grid'`). `?display=list` открывает список.
  Таблица пересобирается в `render()`, потому что `table()` выполняется до
  гидрации `#[Url]`; `columns()` замыканием не принимает. Если добавлять строковые действия или
  переключаемые колонки, перепроверить эту пересборку: она пропускает `cacheMountedActions` и
  `initTableColumnManager`.
- **Фильтры над таблицей сворачиваются** (`FiltersLayout::AboveContentCollapsible`). Панель
  стартует закрытой. Значения пишет `persistFiltersInSession` в ключ
  `tables.{md5(Listings)}_filters` (`Listings::filtersSessionKey`). Возврат на `/admin/listings`
  без `filters` в адресе поднимает их из сессии. Адрес с `filters` важнее сессии. Сброс формы
  записывает пустое состояние. Новый вход стирает ключ: `session()->regenerate(true)` меняет id,
  но оставляет данные в памяти запроса, поэтому слушатель `Login` вызывает
  `Listings::forgetRememberedFilters()`. Поиск в сессию не кладётся.
- **Направление.** Фильтр виден, только если `OrgAccess::directions()` вернул оба: нет команды
  (владелец, владелец компании) или включены «оба направления». Команда продажи запрашивает
  только продажу, команда помесячной сдачи — только её; чужое значение в адресе запрос не
  расширяет. Тип недвижимости при этом остаётся фильтром внутри разрешённого направления.
- `$card` и `$error` карточки помечены `#[Locked]`: состояние карточки нельзя подменить из браузера.
- URL из API (фото, ссылка на источник) попадают в разметку только с схемой `http(s)` (`Listing::safeUrl`).
- Повторы HTTP (2 попытки всего): только при ошибке соединения и на 500 / 502 / 504. **503
  (`query_timeout`) не повторяем** — API просит не слать тот же запрос снова; три попытки по 10 с
  повесили бы страницу на 30 с.
- `created_since` / `created_until` уходят простой датой `Y-m-d`. API трактует `created_until`
  без времени как весь день.
- Объявления не кешируются (решение «мгновенно»); справочники — сутки. Пустой или не-массив `data`
  справочника **не кешируем**, а бросаем `RealEstateUnavailable`: иначе осечка прокси ломает экран на сутки.
- **Пометка «API недоступен».** Ключ `real-estate:down` в общем кеше на 30 с плюс флаг `$down` экземпляра
  клиента; пока пометка есть, любой вызов сразу падает `RealEstateUnavailable`, без новых таймаутов.
  Ставится **только** на `ConnectionException` (таймаут, обрыв) и на 502 / 504 после повторов — признаки
  шлюза, а не запроса. 500 (после повтора), 503 и любые 4xx пометки **не** ставят: 500 и 503 дают
  `RealEstateUnavailable`, неожиданный 4xx — `RealEstateBadRequest` с `Log::error`. Пометка общая для
  всех пользователей (кеш), поэтому ставить её на «плохой» запрос одного агента нельзя: он выключил бы
  экран всей группе на 30 с. Тесты — `RealEstateClientTest` (`request_fault…`, `gateway_fault…`).
- **Формат ответа.** 200, в котором `data` не массив, нет `id` / `source` или мусор в датах, — это
  `RealEstateUnavailable` + `Log::warning`, а не 500 (`RealEstateClient::parsed()`). `phones_e164`
  фильтруется по `is_string`.
- **Фильтры из адреса недоверенные.** `ListingQuery` пропускает id только вида `[1-9]\d{0,17}`,
  числа — `is_numeric` и не меньше нуля, `source` — из белого списка; невалидное = фильтр не задан, в API
  не уходит (иначе 422 и ложные записи «баг GS Home» в журнале). Район не запрашивается без
  числового города. Ведущие нули (`007`) и `0` — «не задан». Поиск обрезается до 100 символов
  (`max:100` в API) и не шлётся, если после обрезки короче 2. Даты «с» и «по» в обратном порядке `ListingQuery` меняет местами (в форме у «с» стоит `maxDate`, у «по» — `minDate`, оба поля `live()`: это подсказка, гарантия — перестановка в `ListingQuery`; решение — [[02_Решения]], 2026-10-11).
  `?search[]=…` сбрасывается в `Listings::mount()` и `hydrate()` (массив через `$wire.set`), а `getTableSearch()` проверяет
  `is_scalar`. Карточка с id не из цифр или `0` — 404 до запроса к API.
- «Чужие» (`exclude_phones`) — номера **только видимых смотрящему** компаний, не всей группы (иначе разность
  множеств открывает скрытые компании, см. 5.7). Решение — [[02_Решения]], 2026-10-11.
- **Страница по «Назад».** Курсор API лежит в `?page=`. Числовой резолвер Livewire заменяет нечисловое
  значение на `1`, поэтому `Listings::mount()` сначала вызывает `Paginator::resolveCurrentPage('page')`
  (он подключает синхронизацию с адресом), а затем кладёт курсор в `$this->paginators['page']`
  (строка не длиннее 2000 символов, не из одних цифр). Тесты `test_cursor_in_url_goes_to_the_api` и `test_cursor_is_kept_in_sync_with_the_url`
  (второй ловит удаление `resolveCurrentPage`: проверяет хук `PaginationUrl` на `paginators.page`).
  Имя `page` зашито: у таблицы нет идентификатора, а `getTablePaginationPageName()` в `mount()`
  недоступен (таблица ещё не собрана). Добавится `queryStringIdentifier` — поправить.
- Курсор из URL с другой сортировкой API отвергает (422 только по полю `cursor`). Клиент бросает
  `RealEstateStaleCursor` без `Log::error`, а `Listings::fetch` молча повторяет запрос с первой
  страницы и сбрасывает `paginators.page`. 422 по другим полям остаётся `RealEstateBadRequest` (баг клиента, `Log::error`).
- **Справочники.** Кешируются на сутки, только если `data` — непустой список массивов, у каждого есть `id`
  (у `deal-types` ещё и `slug`); иначе `RealEstateUnavailable` без кеша.
- Модалка «Связаться» без кнопки копирования, фото галереи открываются внешней ссылкой в новой вкладке.
  Справочники запрашиваются без `lang`: язык выбирается при показе (`RealEstateClient::title()`).
  Направление — `SelectFilter` в панели фильтров.
