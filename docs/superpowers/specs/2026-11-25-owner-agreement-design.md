# Несколько агентов на объекте, договор с собственником, валюта и отчёт — дизайн

Дата: 2026-11-25, версия 2 (26.11). Статус: на согласовании.
Версия 1 (только договор на эксклюзивном закреплении) — в истории git этого файла.

## Зачем

1. **Работа с собственниками.** Агентство ведёт её в ручных журналах (пример — журнал
   агента `lkhub64`, ~1000 записей за март–октябрь 2026): агент находит объявление
   собственника, дозванивается, договаривается о цене и комиссии и выкладывает квартиру от
   агентства на MyHome и SS.GE. Руководитель хочет видеть эту работу в системе и строить по
   ней отчёты.
2. **Объект неэксклюзивен (новое, 25.11).** Одну квартиру могут вести несколько агентов
   одновременно и независимо: каждый сам договаривается с собственником, выкладывает
   объект, ведёт своих клиентов, назначает показы. Деньги получает тот, кто реально сдал
   или продал. Сейчас система построена на «один объект — один агент» (уникальный индекс,
   передача, закрытие, плашка «в работе у X»).
3. **Валюта.** Аренда — в лари, продажа — в долларах; агент может выбрать другую.
   Суммы до закрытия — информационные. В момент «Сделка состоялась» (и сохранения договора)
   система запоминает официальный курс НБГ, чтобы потом строить отчёты в любой валюте.

**Успех:** несколько агентов ведут одну квартиру, не мешая друг другу; агент за полминуты
вносит договор с собственником; руководитель за период видит по каждому агенту договоры,
условия, сданное нами, ожидаемую и полученную комиссию — в ₾ или $; директору это
показывают на компании `Demo`.

**Анти-цели:** не повторять кашу журнала (свободный текст в колонке комиссии, район
99 написаниями, `$` пометкой); не добавлять агенту шагов сверх нужного; не вводить то,
что система знает из объявления; не раскрывать агенту чужие условия с собственником и
чужих клиентов; не допустить «сдали двое».

## Термины

| слово | что это | в базе |
|---|---|---|
| **объект** | квартира: группа дублей объявлений (или одно объявление) | новая таблица `listing_objects` |
| **участие** («в работе у меня») | работа одного агента с объектом: его договор с собственником, предпочтения, активность | `listing_pins` (как сейчас, но не уникальна на объект) |
| **договор** | условия агента с собственником | колонки на `listing_pins` |
| **сделка** | клиент × участие агента | `deals` (как сейчас) |

## Что значат колонки журнала (со слов владельца проекта, 25.11)

| колонка | смысл | в системе |
|---|---|---|
| თარიღი | дата записи | дата договора, ставится сама |
| MYHOME / SS.GE | ID **наших** объявлений агентства | два необязательных поля договора |
| მეპატრონის ID / ნომ / მისამართი | объявление собственника, телефон, адрес | из объявления |
| зелёная колонка | за сколько агент договорился сдавать | вводит агент |
| მეპ თანხა | сколько хотел собственник | цена объявления; агент может поправить |
| თანამშრომლობა | комиссия агентства с собственника | выпадающий список |
| последняя | район | из объявления (`subdistrict_id` снимка) |

Колонка комиссии в журнале `lkhub64`: 50% — 716, 100% — 347, пусто — 321, «?» — 302,
70% — 42, 30% — 17, фикс. сумма — ~28, «fake» — 14, единично 60%, «6 мес. 50%».
Пусто и «?» — ещё не договорились; «fake» — исход работы с объектом.

## Подходы

**Модель «несколько агентов на объекте»** (разбор кода 25.11):
- А. Просто снять уникальность закрепления. Дёшево, но фактам об объекте («сдан», «fake»,
  снимок цены) негде жить; «закрыть у всех» ищет соседей по устаревающему `pin_key` и
  не даёт общей точки блокировки — «сдали двое» возможно.
- **Б. Объект + участие — выбран.** Тонкая таблица объекта (ключ, снимок, статус, кто
  сдал) — одна строка на квартиру, она же точка блокировки; `listing_pins` становится
  участием агента со ссылкой на объект. Сделки по-прежнему ссылаются на участие.
  Примерно вдвое больше работы, чем А, но закрытие для всех, гонки и отчёты без дублей
  решаются прямо.
- В. Пин = объект, участники отдельно. Ломает всё, что читает `pin->user_id`; выгод перед
  Б нет.

**Договор с собственником:** поля на участии, отдельная кнопка (не форма при «Взять в
работу») — выбрано владельцем проекта 25.11. Отдельная сущность с версиями и экран-
таблица как журнал — отклонены.

**Валюта:** «всё в лари, $ свободным текстом» — отклонено владельцем 26.11 в пользу
«₾ для аренды, $ для продажи, курс НБГ запоминается при фиксации суммы».

## Решения владельца проекта

1. Один объект ведут несколько агентов независимо; деньги — тому, кто сдал/продал.
   **Аккаунт = рабочее место (26.11):** при смене сотрудника аккаунт не архивируют — меняют
   пароль и отдают новому человеку; его участия и договоры продолжаются под тем же аккаунтом.
   Передача участия другому агенту остаётся — руководитель переключает объект при необходимости.
2. Кнопка «Предпочтения собственника» → «Добавить договор» / «Договор с собственником»;
   одно окно: договор + предпочтения. Открывается, когда агент дозвонился, не при взятии.
3. Комиссия — выпадающий список из того, что есть в журнале; переделаем, если директор
   даст подробности. **Аренда:** 100% · 50% · 70% · 30% месячной аренды · фиксированная
   сумма · % в течение N месяцев · другое. **Продажа:** 1% · 2% · 3% от цены · фикс · другое.
4. Валюта: аренда по умолчанию ₾, продажа $; агент может выбрать другую. Только ₾ и $.
   При «Сделка состоялась» сохраняется курс НБГ; отчёты пересчитывают по нему.
5. Меньше кнопок и выборов, но с «другое» для редких случаев.

## Правила работы нескольких агентов

Ответы директора ещё не получены (вопросы отправлены 26.11). До ответа строим по
предложенным правилам ниже; каждое — отдельное место в коде, чтобы поменять одно, не
трогая остальные.

| # | правило | по умолчанию |
|---|---|---|
| R1 | Один сдал/продал | объект закрывается у всех; участия других закрываются с причиной `closed_by_other`, их открытые сделки → `unavailable` (в неудачи не идут); другим — уведомление «сдан агентом X» |
| R2 | «Объект недоступен» | причина решает охват: «сдан/продан не нами», «не собственник (fake)» — закрывает объект для всех (журнал + уведомление остальным); «собственник отказал мне», «другое» — только моё участие |
| R3 | Один клиент у двух агентов по одной квартире | разрешено; при открытии сделки предупреждение «этот клиент уже в сделке по этой квартире у X» (не запрет); деньги — по выигранной сделке |
| R4 | Видимость | на карточке: «Ведут: Агент A, Агент B» (кто видит объект по нынешним правилам — тот видит имена ведущих своей компании и компаний по обмену); чужой договор и чужие сделки — только руководителю по ступени (`OrgAccess`); сравнение договоров по объекту — только руководителю (решение владельца 26.11) |
| R5 | Разные компании | могут вести один объект, если между ними включён обмен; иначе — независимо, не видя друг друга |
| R6 | Совместная сделка с партнёром и долей | остаётся как есть |
| R7 | Предпочтения собственника | свои на каждом участии |
| R8 | Передача | остаётся как сейчас (кнопка «Передать», права `Pins::canReceive`): участие целиком — с договором, предпочтениями и открытыми сделками — переходит другому агенту. Нельзя передать тому, у кого уже есть активное участие в этом объекте (отказ с понятным текстом). Архив не трогает участия: аккаунт = рабочее место, при смене человека меняют пароль |
| R9 | Собственник отказал одному | остальные продолжают (R2) |
| R10 | Лимит ведущих на объект | нет |

## Дизайн

### Данные

**`listing_objects`** (новая):

| колонка | смысл |
|---|---|
| `id` | |
| `object_key` | `c:<cluster>` или `l:<listing>` — как нынешний `pin_key` |
| `listing_id`, `cluster_id` | последнее известное объявление и группа |
| `direction` | аренда / продажа |
| `status` | `open` / `closed` |
| `closed_reason` | `won` / `rented_elsewhere` / `fake` |
| `closed_at`, `closed_by` (FK users), `won_deal_id` (FK deals) | кто и чем закрыл |
| снимок: `price_usd`, `price_gel`, `rooms`, `subdistrict_id`, `title`, `snapshot_at` | переезжает с `listing_pins` |

UNIQUE(`object_key`) WHERE status = 'open'. Поиск объекта по объявлению — как сейчас
`activeForIds`: по ключу группы **или** по `listing_id` (ключ мог устареть). Объект
создаётся при первом «Взять в работу»; закрытый объект не переоткрывается — новое взятие
той же квартиры позже создаёт новый объект (квартиру снова сдают через год).

**`listing_pins`** (участие): + `object_id` (FK, NOT NULL). UNIQUE(`object_id`, `user_id`)
WHERE status = 'active' вместо нынешнего UNIQUE(`pin_key`) WHERE active. Снимок
переезжает на объект (на пине удаляется после миграции). `closed_reason` дополняется:
`closed_by_other`, `merged`, `owner_refused`.

**Договор** — колонки на `listing_pins`:

| колонка | тип | смысл |
|---|---|---|
| `agreed_at` | timestamptz | дата договора; NULL — договора нет; ставится при первом сохранении и не меняется |
| `agreed_by` | FK users | кто внёс (ему засчитывается в отчёте) |
| `agreed_price` | numeric(12,2) | за сколько договорились |
| `agreed_currency` | `GEL`/`USD` | валюта цены и фиксированной комиссии; по умолчанию ₾ аренда, $ продажа |
| `owner_price` | numeric(12,2) | цена собственника в той же валюте: подставляется из объявления, если там есть цена в этой валюте, агент может поправить; может быть NULL |
| `commission_kind` | `percent` / `fixed` / `percent_months` / `other` | |
| `commission_percent` | smallint | 1–100 |
| `commission_months` | smallint | для `percent_months` |
| `commission_amount` | numeric(12,2) | для `fixed` |
| `commission_note` | varchar(100) | для `other` |
| `available_from` | date | свободна с (аренда) |
| `min_term_months` | smallint | 6 / 12 (аренда) |
| `myhome_id`, `ss_id` | bigint | наши объявления |
| `agreement_note` | text | заметка |
| `agreement_rate_id` | FK `exchange_rates` | курс НБГ на дату договора |

CHECK: договор целиком или никак (`agreed_at`, `agreed_by`, `agreed_price`,
`agreed_currency`, `commission_kind` — все NULL или все заданы); поля комиссии
соответствуют виду; проценты 1–100. Пункты списка — enum `CommissionOption`
(вид + процент), отдельно для аренды и продажи; добавить пункт — одна строка.

**Курс** — новая таблица `exchange_rates`: `date` (дата действия курса), `currency`
(`USD`), `rate` numeric(12,6) — сколько ₾ за 1 $, `source` (`nbg`), `fetched_at`.
UNIQUE(date, currency). Источник — открытый API НБГ без ключа
`https://nbg.gov.ge/gw/api/ct/monetarypolicy/currencies/en/json/?currencies=USD&date=YYYY-MM-DD`
(поля `rate`, `quantity` — делить на quantity, `validFromDate`). Курс берётся по дате
события в часовом поясе Тбилиси.

**Сделка:** + `rate_id` (FK `exchange_rates`) — заполняется при «Сделка состоялась».
`config('crm.currencies')` остаётся `['USD','GEL']`. Валюта цены и комиссии сделки по
умолчанию — по направлению (₾ аренда, $ продажа).

### Курс: как берётся

- `App\Money\Rates::for(date)` — из таблицы; нет строки — запрос к НБГ, запись, возврат.
- При «Сделка состоялась» и сохранении договора: пытаемся взять курс **синхронно с
  коротким таймаутом (3 с)**; не вышло — сохраняем без курса и ставим джобу
  `FetchNbgRate(date)` с повторами; джоба проставляет `rate_id` всем записям этой даты
  без курса. Агент ошибки не видит.
- Ежедневно (планировщик) — курс на сегодня, чтобы почти всегда был в таблице.
- Сумму после закрытия поправить можно, курс не меняется.
- Пересчёт: ₾ → $ = сумма / rate; $ → ₾ = сумма × rate. Округление до целых в отчёте.

### Окно «Договор с собственником»

```
Договор с собственником
────────────────────────────────────────
Договорились сдавать   [ 900 ] [₾ | $]          (₾ по умолчанию для аренды, $ для продажи)
Цена собственника      [ 950 ]  ← из объявления, если есть в этой валюте; можно поправить
Комиссия               [ 50% месячной аренды      ▾]
   фиксированная  →    [ 300 ] (в валюте цены)
   % × N месяцев  →    [ 50 ] % × [ 6 ] мес.
   другое         →    [ текст до 100 символов ]
Свободна с             [ дата ]            аренда, необязательно
Минимальный срок       [ — ▾ ] 6 мес. / 1 год   аренда, необязательно
Наши объявления        MyHome [ ID ]   SS.GE [ ID ]   необязательно
── Кому готов сдать ──  нынешние поля предпочтений (аренда)
Заметка                [ текст ]
                                   [ Сохранить ]
```

- «Договорились» и «Комиссия» обязательны только вместе: не заполнено ни одно —
  сохраняются только предпочтения и заметка, договора нет, кнопка остаётся «Добавить договор».
- Только активное участие; править может тот, кто управляет участием (`Pins::canManage`).
  Журнал: `pin.agreement_saved`.

### Карточка объекта

```
Ведут: Agent 724 (вы) · Agent 39 · Agent 664             [Взять в работу] — если вы ещё не ведёте
Ваш договор 12.11: 900 ₾ (собств. 950) · 50% · свободна с 07.08 · MyHome 20639604
                                                [Договор с собственником] [Недоступен] [Освободить]
```

- «Ведут» — по R4. Агент чужой договор не видит.

### Договоры по объекту — сравнение для руководителя (решение владельца 26.11)

Один объект — несколько договоров с собственником на разных условиях; **все хранятся**,
ни один не перезаписывает и не обнуляет другой (каждый — на своём участии). Руководитель
видит на карточке объекта блок «Договоры по объекту»:

```
Договоры по объекту                                    ожидаемая комиссия
★ Agent 39    14.11  1 000 ₾ (собств. 1 000)  100%            1 000 ₾
  Agent 724   12.11    900 ₾ (собств.   950)   50%              450 ₾
  Agent 664   18.11    $340 (собств. $350)     фикс $100       ≈ 259 ₾
  Agent 113   20.11    850 ₾                    другое: «...»        —
```

- Видят **только руководители** — те, кому `OrgAccess` показывает сотрудника-держателя
  (тимлид своих агентов, владелец компании — своей, владелец группы — всех); каждый
  видит договоры только видимых ему людей. Агент, даже ведущий объект, видит только свой.
- **★ лучший** — наибольшая ожидаемая комиссия агентству в ₾ (формула из раздела отчёта;
  договор в $ переводится по курсу НБГ на дату договора). `other` и договоры без курса
  в выборе лучшего не участвуют; при равенстве — более ранний договор.
- Строка ведёт к карточке сотрудника (телефон), чтобы руководитель мог поручить работу с
  собственником тому, кто договорился лучше.
- Показываются договоры активных участий и закрытых `closed_by_other`/`merged` — история
  договорённостей по квартире не пропадает.
- «Взять в работу» видна, пока вы не ведёте объект и он открыт.
- Закрытый объект: «Сдан 20.11 агентом X» / «Недоступен: fake (отметил X 18.11)».

### «Объект недоступен»

Окно подтверждения с одним выбором причины (обязательным): «Сдан / продан не нами»,
«Не собственник (fake)» — закрывают объект для всех (R2); «Собственник отказал мне»,
«Другое» — только ваше участие. Подпись под выбором объясняет охват.

### Закрытие и гонки

- «Сделка состоялась»: в одной транзакции **сначала** `lockForUpdate` строки объекта,
  потом сделки и участия. Объект уже закрыт → отказ «Объект уже сдан агентом X».
  Иначе: сделка `won` + курс, объект `closed/won`, своё участие `won`, остальные участия
  объекта `closed_by_other`, их открытые сделки `unavailable` (слушатель, как сейчас
  `CloseDealsOnPinClosed`), уведомления ведущим.
- «Недоступен для всех» — та же блокировка объекта первой.
- Все операции, затрагивающие несколько участий, берут блокировку объекта первой —
  порядок блокировок один, взаимных блокировок нет.

### Что убирается / меняется в существующем

- `Pins::take`: отказ только если у этого агента уже есть активное участие в объекте
  (`PinTaken` → «вы уже ведёте этот объект»).
- `Pins::transfer` и кнопка «Передать» остаются (R8): блокировка объекта первой, отказ,
  если у получателя уже есть участие в объекте.
- `activeFor` → `objectFor(listing)` + `myPin(object, user)` + `pinsOf(object)`.
- `Matching`: группировать по объекту; брать предпочтения участия смотрящего (R7);
  объект с несколькими ведущими — одна строка.
- `SnapshotPins` / снимок — по объекту (один запрос к API на квартиру).
- `AgentReport`, `DaySummary`, «Мои объекты»: по агенту — как сейчас; сводные итоги
  руководителя — уникальные объекты.
- Плашка «в работе у X» (`holderLabel`, `MatchRows`) → список ведущих.
- Документы: новая запись в `02_Решения.md` (отменяет «одно закрепление на группу»), `10_Модули_системы.md`, `11_CRM_альфа.md`.

### Миграция прода

На проде (26.11) 6 закреплений, 4 сделки, все закрепления на разных квартирах:
каждому активному/закрытому пину — свой объект (статус объекта по статусу пина),
снимок переносится. Сделке 16 (`won`, 450 USD) — курс НБГ на её `closed_at`.
Дамп базы перед деплоем.

### Отчёт руководителя — раздел «Работа с собственниками»

Страница `AgentReportPage`, правила видимости `OrgAccess::visibleUsers`, тот же период.
**Переключатель валюты ₾ / $** (по умолчанию ₾) действует на все денежные колонки отчёта,
включая нынешний «заработок»; подпись «по курсу НБГ на дату сделки / договора». Записи
без курса (джоба ещё не отработала) — пересчитываются по ближайшему известному курсу и
помечаются «≈».

| показатель | откуда |
|---|---|
| взято в работу | участия, `created_at` в периоде |
| договоров | `agreed_at` в периоде, по `agreed_by` |
| без договора дольше N дней | активные участия без `agreed_at`, старше `crm.stale_days` |
| условия | разбивка по пунктам списка; `percent_months` — «N мес.», `fixed` — «фикс», `other` — «другое» |
| средняя скидка от цены собственника | `1 − agreed_price / owner_price` по договорам с `owner_price` |
| ожидаемая комиссия | по договорам периода (формула ниже), в выбранной валюте |
| сдано / продано нами | участия с договором, закрытые `won` в периоде |
| сдано другими | участия, закрытые `closed_by_other` в периоде (в неудачи не идёт) |
| недоступно | по причинам: не нами · fake · отказал мне · другое · не указана (старые) |
| дней до договора / до сдачи | медианы `agreed_at − created_at`, `closed_at − agreed_at` |

Формула ожидаемой комиссии: `percent` — цена × %; `fixed` — сумма; `percent_months` —
цена × % × N; `other` — не считается, «другое: N шт.».

Под таблицей — разбивка по районам: договоров, средняя цена (в выбранной валюте), скидка.
Период считается по событиям, без когорт. Итоговая строка руководителя считает объекты
уникально.

## Уточнения после проверки (решения исполнителя дизайна, 26.11)

1. **Два открытых объекта на одну квартиру** (объявление вошло в группу, где уже есть
   объект). Поиск объекта по ключу группы или `listing_id` нашёл больше одного — объекты
   **склеиваются в старший**: участия младшего переносятся на старший (`object_id`), снимок
   берётся свежий, младший закрывается с причиной `merged_into` и ссылкой `merged_into_id`.
   Если у агента оказалось два активных участия в одном объекте — младшее закрывается
   `merged`, его открытые сделки переходят на старшее (как при склейке). Склейка идёт под
   блокировкой обоих объектов (по возрастанию id) и вызывается: при «Взять в работу», при
   закрытии, при открытии карточки и ночью в `SnapshotPins`. Гарантия «сдали двое» держится,
   потому что закрытие сначала склеивает, потом блокирует единственный объект.
2. **Объект без ведущих.** Когда закрывается последнее активное участие не «для всех»
   («Освободить», «отказал мне», «другое»), объект закрывается с причиной `abandoned`.
   Повторное «Взять в работу» той же квартиры создаёт новый объект. Причины объекта:
   `won`, `rented_elsewhere`, `fake`, `abandoned`, `merged_into`.
3. **Объект общий для всех компаний** (квартира одна, «сдана» — факт). Имена в
   уведомлениях и в «Ведут» — по нынешним правилам видимости держателя
   (`Pins::holderLabel`): кто не вправе видеть имя, видит «агентом другой компании».
   Компании без обмена: в «Ведут» чужие участия не показываются вовсе; о закрытии объекта
   их агент узнаёт уведомлением без имени.
4. **«Сдано нами»** — участия, закрытые `won` в периоде, **с договором или без** (без
   договора — отдельной цифрой «из них без договора»). **Заработок** — как сейчас, из
   сделки (комиссия при «Сделка состоялась»). **Ожидаемая комиссия** — из договора.
   Это разные колонки, не подменяют друг друга.
5. **Валюта по направлению — только значение по умолчанию в формах.** Существующие данные
   не меняются. Курс по `closed_at` проставляется миграцией **всем** выигранным сделкам
   без курса (на проде сейчас одна — сделка 16).
6. **Передача (R8).** Участие переходит целиком; `agreed_by` не меняется (договор засчитан
   тому аккаунту, кто его внёс). Передача берёт блокировку объекта первой, потом участия.
7. **«Ведут» на карточке:** своя компания и компании по обмену — с именами по правилам
   `holderLabel`; без обмена — не показываются.

Таблица «Данные» дополняется: `listing_objects.merged_into_id` (FK, NULL);
`closed_reason` объекта — `won` / `rented_elsewhere` / `fake` / `abandoned` / `merged_into`.
Миграция прода: пин `active` → объект `open`; `won` → `closed/won`; `released` →
`closed/abandoned`; `unavailable` → `closed/abandoned` (причина «недоступен» у старых
пинов не записывалась).

## Ограничения

PHP 8.5, Laravel 13, Filament 5, PostgreSQL; инварианты — CHECK и частичные уникальные
индексы в базе; права — только `OrgAccess` / `Pins::canManage`; переводы ka / ru / en.
Тесты PHPUnit: несколько участий в объекте, закрытие для всех и «сдали двое» (две
транзакции), R2/R3/R8, договор (права, CHECK, `agreed_at` не меняется), курс (кэш, таймаут
→ джоба, `quantity`), формула комиссии, отчёт в ₾ и $, миграция данных, демо-команда.

## Порядок работ (для плана)

1. Объект + участие, миграция, закрытие/гонки, карточка «Ведут», передача с проверкой получателя.
2. Курс НБГ и валюта сделки по направлению.
3. Договор с собственником, причина «недоступен», сравнение договоров для руководителя.
4. Отчёт «Работа с собственниками» и переключатель ₾ / $.
5. Демо-команда, показ директору.

Каждый шаг — отдельный PR, прод можно обновлять после каждого.

## Не в этой итерации

Автопоиск наших объявлений по группе дублей; тенденция по неделям; договор как документ
(файл, эксклюзив); фактически полученная комиссия с собственника; валюты кроме ₾ и $.

## Оставлено исполнителю

Раскладка окон и карточки в Filament, тексты переводов, имена событий журнала, индексы
под отчёт, точный текст уведомлений.
