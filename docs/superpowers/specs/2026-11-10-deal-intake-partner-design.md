# Анкета клиента, цена и общая сделка — дизайн

Дата: 10.11.2026. Основа — [[13_Процесс_агентов]] (рассказ агентства, 10.11.2026), пункты 3, 5 и 2
раздела «Что это меняет». Пользователь отказался от вопросов: решения ниже — мои, они собраны в
конце, в «Решения, которые я принял».

## Зачем

Агенты описали, как реально ведут клиента. Три вещи CRM-альфа сейчас записать не может:

1. **Ответы клиента на первом звонке.** У аренды и продажи разные вопросы: кто будет жить и на
   какой срок — или наличные и ипотека. Сейчас они остаются в голове агента или в заметках.
2. **Цена по сделке.** В общем чате агенты пишут «1200/300» — цена квартиры и комиссия. Цены в
   сделке нет, есть только заработок при закрытии.
3. **Общая сделка.** Квартира одного агента, клиент другого — в чат дописывают «+ имя второго».
   Сейчас у сделки один агент, второй в CRM не виден, и в отчёте его доля теряется.

Это закрывает вопрос «Покупатель другого агента на закреплённый объект» в
[[10_Модули_системы]] вариантом б — сделку ведут вдвоём, комиссию делят суммой.

## Цели

- Агент заполняет анкету клиента прямо в сделке, во время или после звонка. Вопросы зависят от
  направления объекта (продажа / помесячная сдача).
- В сделке есть цена: продажная или месячная арендная, с валютой.
- В сделку можно добавить второго агента (партнёра). При закрытии «состоялась» — общая
  комиссия и доля партнёра, обе суммой. Отчёт делит заработок между ними.

## Не цели

- Видимость встреч всей компании, формат сообщения в общий чат, Telegram — ждут ответов
  агентства и модуля 5.
- «Ищем квартиру под клиента» (спрос без объекта: бюджет, район) — отдельная сущность, позже.
- Задаток, предоплата и залог как деньги, которые проходят через агентство — в анкете только
  договорённость «сколько месяцев вперёд», «готов ли на залог». Учёта платежей нет.
- Новые этапы сделки, итоги показа, «X-2» — после ответов агентства.
- Выписка из реестра и файлы в сделке.
- Партнёр из чужого агентства (не из группы) — он не пользователь системы.

## Анти-цели

- Анкета не должна мешать открыть сделку: все поля необязательны, сделка открывается как сейчас.
- Нельзя, чтобы общий заработок пары в отчёте считался дважды или чтобы доля партнёра пропала.
- Партнёр не получает управления чужой сделкой: этапы, показы и закрытие — по-прежнему у
  держателя объекта и его руководителей.

## Как это устроено

### 1. Анкета клиента (`deals.intake`, jsonb)

Хранится на сделке, а не на клиенте: один и тот же человек может снимать квартиру и через
год покупать, ответы относятся к конкретному запросу. Набор вопросов — по направлению пина
(`listing_pins.direction`).

**Помесячная сдача:**

| поле | ключ | ввод |
|---|---|---|
| Кто будет жить | `occupants` | текст, до 255 (мать с ребёнком, 2 студентки, семья с ребёнком…) |
| Срок | `term` | список: 6 месяцев, 1 год, другое |
| Предоплата, месяцев вперёд | `prepay` | список: 1, 1.5, 2, 3, первый и последний |
| Животные | `pets` | да / нет |
| Готов платить залог | `deposit_ok` | да / нет / не обсуждали |

**Продажа:**

| поле | ключ | ввод |
|---|---|---|
| Цель | `purpose` | для жизни / инвестиция |
| Как покупает | `payment` | наличные / ипотека |
| Наличные: нужна помощь банка | `bank_help` | да / нет (видно при «наличные») |
| Ипотека: первоначальный взнос | `down_payment` + `down_payment_currency` | сумма + USD/GEL (видно при «ипотека») |
| Хочет скидку | `wants_discount` | да / нет |

Общие для обоих: `notes` — свободный текст, до 2000.

- Ключи и допустимые значения — в одном месте, класс `App\Crm\DealIntake` (по образцу
  `DealStages`): список полей на направление, проверка, подписи. Неизвестный ключ или значение
  отвергаются на сервере, а не только формой.
- Пустые поля в jsonb не пишутся. По умолчанию `intake = {}`.
- Правит анкету тот, кто управляет сделкой (`Deals::canManage`), пока сделка открыта.
  Закрытую — никто, как и всё остальное в закрытой сделке.
- В журнал — событие `deal.intake_changed` со списком изменённых полей «было → стало».
- На карточке сделки — блок «Анкета клиента» и кнопка «Изменить анкету» (действие с формой).

### 2. Цена по сделке (`deals.price`, `deals.price_currency`)

- `decimal(14,2)` + `char(3)`, оба nullable. Для аренды — цена в месяц (подпись поля зависит
  от направления: «Цена» / «Аренда в месяц»).
- Вводится в той же форме, что и анкета. Валюты — `config('crm.currencies')`.
- Цену не подставляем из объявления Real Estate: объявление может поменяться, а в сделке
  нужна договорённая цена. Подсказка-плейсхолдер — текущая цена объявления, если есть.

### 3. Партнёр по сделке

Новые поля `deals`: `partner_user_id` (nullable FK на `users`), `partner_share` (`decimal(14,2)`,
nullable). Валюта доли — та же, что у `amount`.

**Кто может быть партнёром.** Активный пользователь с ролью «сотрудник» или «тимлид», не сам
агент сделки, из компании агента сделки или из компании, связанной с ней включённым обменом.
Проверка — новый метод `OrgAccess::canPartner(User $agent, User $candidate): bool`, на основе
`identifiableCompanyIds()` агента сделки. Направление партнёра не проверяем: клиента на
продажу может привести агент из аренды.

**Кто добавляет и снимает.** Тот, кто управляет сделкой, пока она открыта. Один партнёр на
сделку. Смена или снятие — в журнал (`deal.partner_set`, `deal.partner_removed`).

**Что видит партнёр.** Сделку и её показы в списке «Сделки» и на карточке — только чтение.
Клиента сделки — карточку клиента (как агент, который вёл с ним сделку). Кнопки этапов,
показов, анкеты и закрытия ему не видны, а сервер их отвергает (`Deals::canManage` партнёра
не включает). Руководители партнёра видят сделку по той же ступени, что и его самого.

- `DealPolicy::view` — агент сделки, партнёр или те, кто видит одного из них по ступени.
- `DealResource::getEloquentQuery` — `user_id` или `partner_user_id` среди видимых.

**Закрытие «состоялась».** Форма `win`: общая комиссия (`amount`, как сейчас) и, если есть
партнёр, — доля партнёра (`partner_share`), обязательная. `0 < partner_share < amount`.
Подпись поля «Сумма» меняется на «Комиссия агентства» — так понятнее, что это не цена.

**Если партнёр ушёл.** Партнёр в архиве или заблокирован — остаётся в сделке, как агент:
история не переписывается. Добавить новым партнёром такого человека нельзя.

**Если объект передали.** Партнёр остаётся. Если новый держатель и есть партнёр — партнёр
снимается, в журнал пишется причина.

### 4. Отчёт руководителя

`AgentReport` — заработок:

- агенту сделки: `amount − coalesce(partner_share, 0)`;
- партнёру: `partner_share` по сделкам, где он партнёр.

Сделка засчитывается в «состоялось» обоим (счётчик сделок агента и отдельный счётчик
«в паре»). Пины, показы, время на этапах — только агенту сделки, как сейчас.

### 5. Миграция и старые данные

Одна миграция: `intake jsonb default '{}'`, `price`, `price_currency`, `partner_user_id`,
`partner_share`. CHECK-и в PostgreSQL: `partner_user_id <> user_id`;
`partner_share is null or (partner_share > 0 and amount is not null and partner_share < amount)`;
`price` и `price_currency` — оба null или оба заданы. Старые сделки получают пустую анкету и
без партнёра — отчёт по ним не меняется.

### 6. Подписи

`lang/{ru,en,ka}/gshome.php`, ключи `crm.intake.*`, `crm.deals.partner*`, `crm.deals.price*`.
Грузинский — из слов агентства в [[13_Процесс_агентов]] (они сами так говорят: ბე, დეპოზიტი,
იპოთეკა, ქეში), остальное — машинный перевод с пометкой проверить.

### 7. Демо и тесты

- `CrmDemo`: анкета у части сделок обоих направлений, одна сделка в паре, одна закрытая в паре.
- Тесты `tests/Feature/Crm/`: проверка анкеты (чужой ключ, значение вне списка, закрытая
  сделка, чужое направление), права партнёра (видит, но не управляет; кандидат из компании без
  обмена — отказ), закрытие с долей (граничные суммы), отчёт делит заработок, CHECK-и
  срабатывают в обход модели.

## Где менять

| что | где |
|---|---|
| поля анкеты, проверка, подписи | новый `App\Crm\DealIntake` |
| анкета, цена, партнёр, `win` с долей | `App\Crm\Deals` |
| кто может быть партнёром | `App\Access\OrgAccess::canPartner()` |
| видимость сделки партнёру | `App\Policies\DealPolicy`, `DealResource::getEloquentQuery` |
| карточка, кнопки | `DealInfolist`, `ViewDeal` |
| отчёт | `App\Crm\AgentReport`, `AgentReportRow` |
| передача объекта | `App\Listeners\ReassignDealsOnPinTransferred` |
| журнал | константы в `App\Crm\Journal` |

## Решения, которые я принял (проверить при чтении)

1. Анкета живёт на сделке, не на клиенте.
2. Анкета — jsonb с белым списком ключей в коде, а не колонки: отчёт по ней не считает, а
   вопросы агентство ещё будет менять.
3. Набор вопросов — мой перевод рассказа агентства; списки значений (срок, месяцы
   предоплаты) взяты из их текста.
4. Партнёр один на сделку, из той же компании или из компании с включённым обменом.
5. Партнёр только смотрит, управляет сделкой держатель объекта.
6. Доля партнёра — суммой, в валюте комиссии; сделка в отчёте засчитывается обоим, деньги
   делятся.
7. Цена в сделке вводится руками, из объявления не копируется.
8. Поле «Сумма» при закрытии переименовывается в «Комиссия агентства».
