# Среда разработки

Основная и единственная среда — Docker на OrbStack (`compose.yaml`). MAMP для
GS Home не используется. Образцы — `compose.yaml` Real Estate и BigMed.

## Сервисы и адреса

| сервис | что | адрес |
|---|---|---|
| `web` | nginx, TLS снимает OrbStack | https://gshome.local, панель `/admin`, Horizon `/horizon` |
| `app` | php-fpm 8.5, artisan, composer | — |
| `horizon` | очереди (держит код в памяти) | — |
| `postgres` | PostgreSQL 17, базы `gshome` и `gshome_test` | `127.0.0.1:5433` (для PhpStorm) |
| `redis` | очереди, кеш | — |
| `mailpit` | ловит всю почту | https://mail.gshome.local |
| `scheduler` | планировщик, профиль `scheduler` | — |
| `test` | сьют, профиль `tools` | — |
| `node` | Node 24, сборка фронта, профиль `tools` | — |

Порты: 5432 занят Postgres Real Estate, 3307 — MariaDB BigMed.

## Команды

```bash
docker compose up -d                          # всё
docker compose exec app php artisan …         # artisan
docker compose exec app composer …            # composer — только в контейнере
docker compose run --rm test composer test    # сьют — только в test
docker compose run --rm node npm run build    # фронт
docker compose restart horizon                # после правки джоб
```

Фронт собирается только в контейнере `node` (`npm ci && npm run build`); `public/build` в git не
входит, после `git pull` сборку нужно повторить. Тема панели —
`resources/css/filament/admin/theme.css` (Tailwind видит `app/Filament` и `resources/views/filament`).

Первый владелец — `docker compose exec app php artisan gshome:owner`; демо-структура для
локальной работы — `docker compose exec app php artisan db:seed --class=OrgDemoSeeder`
(пароль у всех `password`).

**Composer — только в контейнере.** Composer из MAMP на хосте ставит пакеты под
PHP 8.4 (Symfony 8), и контейнер падает на `platform_check.php`. Защита — прибитый
`config.platform.php = 8.5.11` в `composer.json`, но надёжнее не звать его с хоста вовсе.

## Проверка в браузере агентом

Вход по паролю агенту разрешён только на `localhost` / `*.localhost` / `*.test`, а OrbStack
раздаёт только `*.local`. Поэтому для проверки агентом поднимается второй nginx того же стека на
`http://gshome.localhost:8088` — в `compose.override.yaml` (сервис `web-localhost`, конфиг
`tmp/nginx-localhost/`). Оба файла вне git, рабочий стек не затрагивают. Без HTTPS — Filament
строит ссылки по адресу запроса.

## Связь с Real Estate

Из контейнера `app` адрес `https://real-estate.local` доступен напрямую (OrbStack), сертификат
OrbStack PHP в контейнере доверяет — проверку TLS не отключать.

| `.env` | значение |
|---|---|
| `REAL_ESTATE_API_URL` | `https://real-estate.local/api/v1` |
| `REAL_ESTATE_API_KEY` | ключ клиента `re_live_…` — выдаёт Real Estate: «Система → API-клиенты» → клиент → «Ключи». В git и чаты не класть |

В коде — `config('services.real_estate.url')` и `config('services.real_estate.key')`, заголовок
`Authorization: Bearer`. Справочник API — `~/Sites/real-estate.devstudio.ge/docs/RealEstate/16_API.md`.
Проверка связи: `GET /me` (клиент, срок ключа, лимит в минуту). Стек Real Estate поднимается
отдельно, из его каталога.

## Оснастка `bin/`

Скрипты лежат вне репозитория (`.gitignore`), как в BigMed: это оснастка рабочего
места. Если `bin/` нет — восстановить по BigMed, а не делать работу руками.

| скрипт | когда | что делает |
|---|---|---|
| `bin/preflight.sh` | начало сессии | сервисы, PHP, кеш конфига, панель, HTTPS, база, Real Estate, модуль PhpStorm, **самопроверка PHPStan** |
| `bin/preflight.sh --ide-probe` | проверить инспекции IDE | оставляет файл с ошибками для `get_file_problems`; убрать — `--clean` |
| `bin/ship.sh --quick` | по ходу работы | Prettier, пробелы, Pint, PHPStan — без сьюта |
| `bin/ship.sh` | перед PR | то же + полный сьют, один вердикт |
| `bin/ship.sh --pr "Заголовок"` | создать PR | проверка, push, `gh pr create` (описание — `.pr-body.md`) |
| `bin/deploy.sh` | после слияния в `main` | выкладка `origin/main` на сервер и проверка ответа сайта — см. «Сервер» |

Скрипты работают, только если стек поднят **из этого же каталога**: имя
compose-проекта общее для всех worktree, и чужой стек выглядел бы своим.

HTTPS проверяется системным `/usr/bin/curl`: первым в PATH стоит curl из MAMP, он
не видит связку ключей macOS и считает недоверенным доверенный сертификат OrbStack.

## Сервер

Прод — https://gshome.devstudio.ge, сервер `re-panel` (Virtualmin), тот же, что у Real Estate.
Домены за Cloudflare, поэтому SSH — по IP, через алиасы в `~/.ssh/config` на Mac:

| алиас | кто | зачем |
|---|---|---|
| `ssh gshome` | пользователь сайта (88.99.95.59:2202, ключ `~/.ssh/id_ed25519_gshome`) | код, artisan, логи |
| `ssh srv` | root | nginx, systemd, Postgres |

| что | где / как |
|---|---|
| код | `/home/gshome/public_html`, ветка `main`; GitHub — deploy key `~/.ssh/github_deploy` на сервере, только чтение |
| nginx | `/etc/nginx/sites-available/gshome.devstudio.ge.conf`: `root …/public_html/public`, скрытые файлы — `deny` |
| PHP | 8.5 (пул FPM от `gshome`), CLI — `/usr/bin/php8.5` |
| база | PostgreSQL **18** (локально 17), база и роль `gshome`; пароль — только в `.env` на сервере, в Virtualmin устаревший |
| очереди | Redis без пароля, префикс `gshome-`; Horizon — systemd `gshome-horizon` (`Restart=always`) |
| планировщик | crontab пользователя `gshome`: `schedule:run` раз в минуту |
| почта | пока `MAIL_MAILER=log` |

**Выкладка — `bin/deploy.sh`** с Mac: `git pull`, `composer install --no-dev`, сборка фронта,
`migrate --force`, `optimize` + `filament:optimize`, `horizon:terminate` (systemd поднимет Horizon заново),
затем проверка, что `/` и `/admin/login` отвечают 200. Выкладывается `origin/main`, не локальная ветка.
Если на сервере правили файлы под git руками — скрипт откажется, чтобы `pull` их не перетёр.

Virtualmin при создании сайта ставит `root` на `public_html` — тогда наружу видны `composer.json`,
`artisan`, а после появления — и `.env`. Пересоздавая сайт в панели, проверять конфиг nginx.
