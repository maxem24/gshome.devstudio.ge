# Оргструктура GS Home — дизайн

Дата: 2026-10-09. Основание: ТЗ ([[01_ТЗ]]) разделы 3, 4.7, 5.6, 5.7; решения ([[02_Решения]]).

## Цель

По любому пользователю система однозначно отвечает на три вопроса:

1. Какие направления объектов он видит (продажа, помесячная сдача)?
2. Каких людей он видит на экранах команды и контроля?
3. Какую метку, компанию, имя и контакт он видит на объявлении, к которому привязан номер телефона?

Владелец управляет структурой из панели: компании, люди, номера, пары обмена.

## Принятые решения (в ходе обсуждения)

- **Роли фиксированные**, без Filament Shield и матрицы прав. Права в ТЗ — это видимость
  строк, вытекающая из места в структуре; матрица действий её не выражает. Shield /
  `spatie/laravel-permission` — позже, если появятся настраиваемые действия.
- **Людей заводит и расставляет только владелец.** Владелец компании видит свою компанию
  только для чтения.
- **В системе только наши компании.** Всё, что не привязалось к нашему номеру, —
  «другая компания». Архивная компания считается не нашей.
- **Плоская модель**: роль, компания, команда, тимлид и флаг «оба направления» — поля
  пользователя. Человек — ровно в одной компании и одной команде. Переводы — правкой
  полей, без истории.
- **Номер принадлежит компании.** Сотрудник — его текущий держатель. При увольнении номер
  передаётся другому сотруднику или остаётся без держателя. Объявления следуют за номером
  сами (принадлежность считается на лету); встречи и заметки остаются за тем, кто их вёл.
- **Номера офиса** — такие же номера компании; держатель номера офиса играет роль
  ответственного.
- **Владельцу номер не заводим.**
- **Нормализация телефонов на сервере** через libphonenumber, только Грузия. Поле ввода —
  `ysfkaya/filament-phone-input` (как в BigMed, версия под Filament 5).

## Данные

### `companies`

| поле | тип | правило |
|---|---|---|
| `name` | string | обязательно, уникально; нормализуется (обрезка краёв, двойные пробелы) |
| `archived_at` | timestamp, null | не пусто — компания вне группы |

### `users` (дополнение существующей таблицы)

| поле | тип | правило |
|---|---|---|
| `role` | string | `owner` · `company_owner` · `team_lead` · `agent` (enum `App\Enums\Role`) |
| `company_id` | fk, null | пусто только у `owner` |
| `direction` | string, null | `sale` · `rent` (enum `App\Enums\Direction`); обязательно у `team_lead` и `agent`, пусто у остальных |
| `team_lead_id` | fk users, null | только у `agent`, обязательно; тимлид той же компании и того же направления |
| `both_directions` | bool | по умолчанию false; значим только у `team_lead` и `agent` |
| `is_active` | bool | по умолчанию true; выключенный не входит в панель |

Email нормализуется в нижний регистр, имя — обрезка и сжатие пробелов.

CHECK-ограничения в PostgreSQL:
- `role` из набора; `direction` из набора или пусто;
- `role = 'owner'` ⇔ `company_id IS NULL`;
- `role IN ('team_lead','agent')` ⇔ `direction IS NOT NULL`;
- `team_lead_id IS NOT NULL` ⇒ `role = 'agent'`.

Межстрочные правила (тимлид из той же компании и направления) проверяет код:
валидация формы и сервис сохранения.

### `phones`

| поле | тип | правило |
|---|---|---|
| `number` | string, unique | E.164, `+995…`; приводится при любой записи |
| `kind` | string | `personal` · `office` — подпись, на логику не влияет |
| `company_id` | fk | обязательно |
| `user_id` | fk users, null | держатель; активный сотрудник той же компании, не `owner` |

Нормализатор `App\Support\PhoneNumber::normalize(string): string` на
`giggsey/libphonenumber-for-php-lite`, регион по умолчанию GE. Принимает любые записи
грузинского номера (`5xx xx xx xx`, `995…`, `+995 …`, с нулём в начале) и бросает
исключение на не-грузинский или невалидный номер. Вызывается из мутатора модели —
нормализуется любой путь записи (форма, сидер, импорт).

### `company_exchanges`

| поле | тип | правило |
|---|---|---|
| `company_a_id` | fk | `company_a_id < company_b_id` (CHECK) |
| `company_b_id` | fk | unique (`company_a_id`, `company_b_id`) |
| `enabled` | bool | |

Модель упорядочивает пару при сохранении, поэтому A–B и B–A — одна строка.

## Правила видимости — `App\Access\OrgAccess`

Единственное место, где живут правила. Политики, фильтры запросов и экраны только
спрашивают его.

### Направления — `directions(User): Direction[]`

- `owner`, `company_owner` → обе.
- `team_lead`, `agent` → своё; обе при `both_directions`.

Направление передаётся в запрос к API Real Estate — чужое направление не приходит вовсе.

### Люди — `visibleUsers(User): Builder`

- `owner` → все;
- `company_owner` → пользователи своей компании;
- `team_lead` → он сам и сотрудники с `team_lead_id` = он;
- `agent` → он сам.

`both_directions` на список людей не влияет.

### Метка объявления — `ownership(User $viewer, ?string $phone): Ownership`

Возвращает объект `Ownership`: `label` (enum `OwnershipLabel`), `companyName`,
`contactName`, `contactPhone` — пусто то, что смотрящему не положено.

Метки: `our_employee` («наш сотрудник»), `linked_company` («сотрудник связанной
компании»), `group_company` («одна из наших компаний»), `other_company` («другая компания»).

Номер находится нормализацией и поиском в `phones`; номер не найден или его компания в
архиве → `other_company`, остальные поля пусты.

| кто смотрит | своя компания | пара с включённым обменом | другая наша компания |
|---|---|---|---|
| `agent`, `team_lead` | `our_employee` + компания, имя, контакт | `linked_company` + компания, имя, контакт | `other_company`, пусто |
| `company_owner` | `group_company` + компания, имя, контакт | то же | то же |
| `owner` | `group_company` + компания, имя, контакт | то же | то же |

Имя и контакт:
- держатель есть и активен → имя держателя, контакт — номер;
- держателя нет (уволен или не назначен) → имени нет, контакт — сам номер (SIM остаётся
  в компании).

## Экраны (Filament, панель `/admin`)

Группа навигации «Оргструктура».

| экран | `owner` | `company_owner` | `team_lead`, `agent` |
|---|---|---|---|
| Компании | всё, включая архив | своя, чтение | нет |
| Люди | всё | своей компании, чтение | нет |
| Номера | всё | своей компании, чтение | нет |
| Обмен между компаниями | всё | нет | нет |

- **Люди — форма:** имя, email, пароль (задать / сбросить), роль, компания, команда,
  тимлид (список по выбранной компании и команде), «оба направления», активен. Поля,
  ненужные роли, скрыты и очищаются при сохранении.
- **Уволить** — действие: выключает человека; модалка со списком его номеров и выбором
  нового держателя (активный сотрудник той же компании) или «оставить без держателя».
- **Номера:** `PhoneInput` с `onlyCountries(['GE'])`, `initialCountry('GE')`, без
  определения страны по IP (урок BigMed: `~/Sites/coda/bigmed.ge/docs/BigMed/46_PhoneInput_в_Filament.md`);
  держатель — из активных сотрудников компании.
- **Обмен:** таблица пар с переключателем `enabled`; создание — две разные компании.
- **Вход:** `User::canAccessPanel()` → `is_active`. Временное «пускаем всех» снимается.

## Запуск

- `php artisan gshome:owner` — создать владельца (имя, email, пароль интерактивно).
- `OrgDemoSeeder` — для локальной работы: две компании, обе команды в каждой, по два
  тимлида с сотрудниками, личные и офисные номера, одна пара обмена (включена). В
  `DatabaseSeeder` по умолчанию не вызывается.

## Тесты

- `OrgAccess::ownership` — каждая клетка таблицы; номер не найден; архивная компания;
  номер без держателя; уволенный держатель.
- `OrgAccess::directions` и `visibleUsers` — по каждой роли, с флагом и без.
- Ограничения базы: владелец с компанией, сотрудник без команды, `team_lead_id` у
  не-сотрудника, дубль пары A–B / B–A, дубль номера в разной записи.
- `PhoneNumber::normalize` — разные записи одного номера → одно значение;
  не-грузинский и мусор → исключение.
- Доступ к экранам по ролям; выключенный не входит; увольнение передаёт номера.

## Вне этапа

Экраны объявлений и вывод метки на них (вместе с API Real Estate), экран тимлида с
активностью, встречи, уведомления, журнал изменений, история переводов.

Для API Real Estate отсюда следует требование: телефоны объявлений отдаются
нормализованными по тому же правилу (E.164, GE).
