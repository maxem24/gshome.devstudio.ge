# Экран объявлений GS Home (этап «просмотр») — дизайн

Дата: 2026-10-10. Основание: ТЗ ([[01_ТЗ]]) разделы 4.1–4.5, 5.6, 5.7; решения ([[02_Решения]]);
требования к API — [[07_Требования_к_API_Real_Estate]]; правила видимости — [[05_Оргструктура]].
API Real Estate — `~/Sites/real-estate.devstudio.ge/docs/RealEstate/16_API.md`.

## Цель

Агент открывает «Объекты», видит объявления только своего направления, ищет нужное фильтрами
за секунды, переключает сетку и список и открывает карточку, на которой сразу понятно, чьё это
объявление и с кем связаться.

## Принятые решения (в ходе обсуждения)

- **Живые запросы к API**, без копии базы в GS Home: «мгновенно» важнее счётчиков и номеров
  страниц.
- **Этап — только просмотр.** Заметки, CRM-статус, история изменений, встречи — следующие этапы.
- **Язык содержимого — язык интерфейса, иначе грузинский оригинал.** Сейчас интерфейс русский.
- **Категории продавца — собственник / агентство / агент** (агент = не собственник и не
  агентство). «Другое агентство» как отдельной категории нет: его закрывает метка принадлежности.
- **Подход — таблица Filament поверх API.** Сетка и список — одна таблица с двумя видами;
  карточка — отдельная страница.
- **Фильтры по телефонам** («сотрудник», «только наши / только чужие») — за выключателем
  `REAL_ESTATE_PHONE_FILTERS`. Дополнение 2026-10-10: Real Estate уже сделал R1–R7 в ветке
  `feature/listings-api` (на проде ещё нет) — локально выключатель включён, на проде включаем
  после выкладки API.
- **Дубли — две метки** (дополнение 2026-10-10, решение владельца проекта). Основная метка — по
  номеру самого объявления. Если она «Другая компания», а в группе дублей есть номер нашего
  человека (`cluster.phones_e164`), рядом вторая: «В группе есть наш сотрудник: Имя» — по тем же
  правилам видимости 5.7 и с «Связаться». API сам ищет `phones` по всей группе.

## Клиент API — `App\RealEstate\RealEstateClient`

Настройки: `config('services.real_estate.url')`, `config('services.real_estate.key')`;
новый ключ `config('services.real_estate.phone_filters')` (`REAL_ESTATE_PHONE_FILTERS`, по
умолчанию `false`).

| метод | что | кеш |
|---|---|---|
| `me(): array` | `GET /me` | нет |
| `listings(ListingQuery $query, ?string $cursor): ListingPage` | `GET /listings` | нет |
| `listing(int $id): ?Listing` | `GET /listings/{id}`; `404` → `null` | нет |
| `dictionary(string $name, array $params = []): Collection` | `GET /dictionaries/{name}` с `lang` | сутки, ключ кеша — имя + параметры + язык |

HTTP: `withToken`, `acceptJson`, таймаут 10 с, `retry(2, 200)` только при сетевой ошибке или
`5xx`. Проверку TLS не отключать.

Ошибки → исключения в `App\RealEstate\Exceptions`:

| ответ | исключение | экран |
|---|---|---|
| нет связи, `5xx` (после повторов) | `RealEstateUnavailable` | «Real Estate недоступен, попробуйте позже» |
| `401`, `403` | `RealEstateAccessDenied` (+ `Log::error` с кодом ошибки API, без ключа) | «Доступ к Real Estate закрыт — ключ истёк или отозван. Сообщите администратору» |
| `429` | `RealEstateRateLimited` (`retryAfter` из `Retry-After`) | «Слишком много запросов, повторите через N с» |
| `422` | `RealEstateBadRequest` (+ `Log::error` с полями) | общий текст ошибки — это баг клиента |

Список и карточка ловят эти исключения и показывают текст уведомлением Filament; список при
этом пуст, карточка — с текстом вместо содержимого.

### Объявление — `App\RealEstate\Listing` (readonly)

Собирается из элемента `data` ответа: `id`, `source`, `sourceUrl`, `dealTypeSlug`, тип,
город, район, адрес, `lat/lng`, `areaTotal`, `rooms`, `floor`, `floorsTotal`, цены
`usd/gel/perSqmUsd`, `negotiable`, `title`, `description`, `images` (url, thumb, main),
`amenities`, `subwayStations`, `sellerCategory` (`SellerCategory`: `Owner`, `Agency`, `Agent`),
`agencyName`, `contactName`, `contactPhone` (как в API), `contactPhoneE164` (`contact.phone_e164` из API; если поля нет — старый API —
`PhoneNumber::tryNormalize(contactPhone)`; замаскированный → `null`),
`hasViber`, `hasWhatsapp`, `clusterListingsCount`, `clusterPhonesE164` (`cluster.phones_e164`,
номера всех активных объявлений группы), `clusterListings` (только в карточке:
`cluster.listings[]` — id, источник, ссылка, продавец, контакт с `phone_e164`, цена),
`sourceCreatedAt`, `updatedAt`.

Язык: `title` / `description` — на `app()->getLocale()`, если пусто — `ka`. Справочные поля
приходят уже на нужном языке через параметр `lang`.

`ListingPage`: `Collection<Listing>`, `nextCursor`, `prevCursor`; превращается в
`Illuminate\Pagination\CursorPaginator` для таблицы Filament.

### Запрос — `App\RealEstate\ListingQuery`

Собирает параметры `GET /listings` из фильтров экрана. **Направление ставит сам**:
`ListingQuery::forViewer(User $viewer, ?Direction $chosen)` берёт
`OrgAccess::directions($viewer)`, сужает выбранным (если выбранное не разрешено —
игнорирует) и подставляет `deal_type_id` по справочнику `deal-types`, сопоставляя
`Direction::Sale → slug sale`, `Direction::Rent → slug rent`. Номера типов сделок в код не
зашиваются. Параметр направления из запроса браузера напрямую в API не уходит.

## Метка принадлежности на странице

`OrgAccess::ownershipMany(User $viewer, array $phonesE164): array<string, Ownership>` — те же
правила, что `ownership()`, но один запрос к `phones` на всю страницу (номера самих объявлений и
номера их групп дублей вместе). `ownership()` переводится на него (один номер = массив из
одного). Пустой/замаскированный номер → «Другая компания».

Вторая метка — `App\RealEstate\ListingOwnership::groupOwnership(Ownership $own, array
$clusterPhones, array $resolved): ?Ownership`: если `$own` не «Другая компания» — `null`; иначе
лучшая из меток номеров группы (кроме номера самого объявления) по старшинству «Наш сотрудник» →
«Сотрудник связанной компании» → «Одна из наших компаний»; если все «Другая компания» — `null`.

## Экран «Объекты» — `App\Filament\Pages\Listings`

Страница Filament с таблицей; `->records(...)` вызывает клиент; `paginationMode(Cursor)`,
25 на страницу. Видна всем ролям; без активного направления (не бывает по CHECK) — пусто.

**Направление.** Переключатель над таблицей: «Продажа» / «Сдача» / «Все» — только разрешённые
значения; при одном направлении переключателя нет.

**Вид.** «Сетка» / «Список», состояние в адресе (`?view=grid|list`).

- **Сетка** (`contentGrid`): фото (главное или первое), цена (продажа — сумма, сдача — «/мес»),
  направление, адрес, комнаты, площадь, тип, метка принадлежности (+ имя, если положено) и, если
  есть, вторая метка «В группе есть наш сотрудник: Имя».
- **Список**: заголовок + адрес, направление, источник, дата появления в источнике, категория
  продавца, метка принадлежности, сотрудник (если положено), вторая метка группы (если есть).

**Фильтры** (над таблицей, состояние в адресе): цена USD от/до; город → район; площадь
от/до; комнаты (1, 2, 3, 4, 5+, несколько); тип недвижимости; источник (`myhome_ge`, `ss_ge`);
«только собственники» (`is_owner=1`); дата появления от/до (`created_since`, `created_until`);
поиск (`q`, от 2 символов). За выключателем
`phone_filters`: «сотрудник» (номера выбранного сотрудника → `phones`), «принадлежность»
(«наши» → `phones` = номера видимых смотрящему компаний; «чужие» → `exclude_phones` = все номера
группы).

**Сортировка:** новые (по умолчанию, `-updated_at`), цена ↑/↓ (`price_usd`), площадь ↑/↓.
Объявления без цены/площади при такой сортировке API не отдаёт — подсказка под переключателем.

**Нет в этапе:** колонка «статус» (API отдаёт только активные; CRM-статус — следующий этап),
общее число найденных, номера страниц (так устроен API).

## Карточка — `App\Filament\Pages\ListingView`, `/admin/listings/{id}`

Доступ: `listing()` → `null` или тип сделки не из `OrgAccess::directions(viewer)` (или не
`sale`/`rent`) → **404**, не 403.

Сверху — **блок принадлежности**: метка, компания и имя (если положено), действие
«Связаться» — модалка с именем и номером нашего держателя номера (ссылка `tel:`, копирование).
У «Другой компании» действия нет. Если есть вторая метка группы — она тут же, со своим
«Связаться».

Ниже: цена по направлению (продажа — USD и GEL, сдача — «в месяц»); галерея (миниатюры, по
нажатию — фото крупно); характеристики (тип, комнаты, площадь, этаж/этажность, адрес + ссылка
«на карте» по `lat/lng`, удобства, метро); описание; контакт продавца из объявления (имя,
телефон как в API, Viber/WhatsApp); ссылка на исходное объявление (новая вкладка);
**группа дублей** — остальные объявления группы (`cluster.listings`): источник со ссылкой,
продавец, цена и метка принадлежности каждого (по тем же правилам).

## Тесты

- **Клиент** (без сети, `Http::fake`, фикстуры по формату `16_API.md`): разбор `Listing`
  (язык с откатом на `ka`, категория продавца, нормализация телефона, маска → `null`); курсор;
  каждая ошибка → своё исключение; `404` → `null`; справочники кешируются, списки — нет.
- **Права:** сдающему в запрос уходит только `deal_type_id` сдачи даже при подделанном
  направлении; «оба направления» → переключатель есть, одно → нет; карточка чужого направления,
  посуточной аренды или залога → 404.
- **Метки:** `ownershipMany` по таблице 5.7 для каждой роли; страница из N объявлений — один
  запрос к `phones`; вторая метка группы — есть только при чужой основной, берётся лучшая по
  старшинству, номер самого объявления не учитывается.
- **Экран:** сетка и список — одни и те же записи; каждый фильтр → правильный параметр API;
  «Вперёд» передаёт `cursor`; при `RealEstateUnavailable` — пустой список и уведомление; фильтры
  по телефонам скрыты при `phone_filters=false`.
- **Вживую:** `http://gshome.localhost:8088` под владельцем, владельцем компании, продающим и
  сдающим сотрудником на демо-данных Real Estate.

## Вне этапа

Заметки, CRM-статус, история изменений, встречи и напоминания. На проде фильтры по телефонам —
после выкладки ветки `feature/listings-api` Real Estate.
