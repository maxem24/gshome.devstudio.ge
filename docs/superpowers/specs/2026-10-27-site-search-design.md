# Поиск на сайтах через сборщика и кнопка «Найти квартиру»

Дата: 2026-10-27. Ветка `feat/site-search`.

## Зачем

С 25.10 сервер Real Estate сам не обходит ни myhome.ge, ни ss.ge. Свежие объявления в его базу
попадают, только когда кто-то ставит поиск: Real Estate отдаёт задание локальному сборщику,
тот обходит выдачу сайтов и возвращает найденное (`~/Sites/real-estate.devstudio.ge/docs/RealEstate/23_Поиск_по_запросу.md`,
API — `16_API_поиск.md`). GS Home этим API не пользуется, поэтому агент видит только то, что уже
лежит в базе Real Estate.

**Успех:** агент в любом месте админки жмёт «Найти квартиру», задаёт фильтры и либо сразу смотрит
базу, либо запускает «Искать на сайтах». Через 1–3 минуты загорается колокольчик «Поиск готов:
N объявлений», по ссылке открывается список найденного с теми же метками принадлежности, что на
экране «Объекты».

## Не делаем сейчас

- Вставку ссылки ss.ge / myhome — нужен новый API в Real Estate (задание `card` сборщику уже
  умеет), отдельная работа там, потом поле здесь.
- Webhook от Real Estate — только опрос. Webhook позже, как ускорение.
- Автоматический поиск на сайтах при каждом изменении фильтра: лимит 60 поисков в час на ключ GS Home
  на всех агентов.
- Отмену поиска (в API Real Estate её нет).

## Что строим

### Кнопка в шапке и окно поиска

- В шапке панели на любой странице — кнопка «Найти квартиру» (ru / en / ka).
- Окно с формой: сделка (только направления агента — `OrgAccess::directions`), город, район,
  подрайон, тип недвижимости, цена USD от/до, комнаты, площадь от/до. Справочники — те же, что у
  фильтров экрана «Объекты».
- Подсказка под формой: для ss.ge нужен город или район и ровно один тип недвижимости, иначе
  ss.ge пропустится и искать будем только на myhome.
- Две кнопки:
  - «Показать в базе» — открывает «Объекты» с этими фильтрами (как ссылка с параметрами);
  - «Искать на сайтах» — ставит поиск и закрывает окно с уведомлением «Поиск запущен, результат
    придёт в колокольчик».

### Поиск на сайтах

- Запись `listing_searches`: кто искал, фильтры, id поиска в Real Estate, общий статус, состояние
  сайтов (`sites` как пришло), сколько найдено, `truncated`, id найденных объявлений (не копии
  карточек — решение 14.10), время запуска и окончания. Ничего не удаляется (SoftDeletes).
- Запуск: `POST /api/v1/search-jobs` (тело — JSON-массивы, без `phones`, `sort`, `cursor`, `per_page`,
  `source`, `lang`). Направление в запрос ставит GS Home, как везде (`OrgAccess::directions`).
  - 202 → поиск в работе; сразу `done` (кеш Real Estate) → результат сразу, уведомление тоже.
  - 422 `filters_required` → «Сузьте поиск: укажите город, район, тип или цену», поиск не создаётся.
  - 429 → «Лимит поисков на сайтах исчерпан, попробуйте позже», поиск не создаётся.
  - Real Estate недоступен → понятное сообщение, не 500.
- Опрос — фоновая задача в очереди (Horizon), не браузер: `GET /search-jobs/{id}` раз в 10 с, пока
  статус не `done | failed | cancelled`. Предел ожидания — 30 минут, потом статус «не дождались»
  (сборщики не на связи) и уведомление об этом.
- Готово → уведомление в колокольчик агенту: «Поиск готов: N объявлений» / «готов частично: …» /
  «не удался». Ссылка ведёт на результат.
- Экран «Мои поиски» (меню CRM): список своих поисков — фильтры коротко, статус, сайты, найдено,
  когда. Руководители видят поиски своих людей (`OrgAccess::visibleUsers`). Повтор поиска — кнопка
  «Искать снова».
- Экран результата: найденные объявления карточками, как сетка «Объекты» — та же метка
  принадлежности и «наш сотрудник» (`ListingRows`, `OrgAccess::ownershipMany`), только объявления
  разрешённого направления. Карточки читаются живыми по id (`ids`, до 100), снятые — пропускаются
  с пометкой. `partial: true` — пометка «неполное, карточку ещё не открывали». Сверху — состояние
  сайтов (`sites.*.message`).
- В журнал (`App\Crm\Journal`): `search.started`, `search.finished` — без фильтров с личными данными
  (их там и нет). В ленту — нет.

## Ограничения

- Ключ API один на всех людей GS Home: 60 поисков в час (лимитер `api-search-jobs` на маршруте
  Real Estate — считается каждый `POST`, даже если ответ из кеша). Поэтому GS Home не ставит второй
  поиск с теми же фильтрами, пока первый у этого же человека идёт, а результат того же человека с
  теми же фильтрами моложе 30 минут показывает без нового запроса. Поднять лимит — настройка
  `api_clients.search_jobs_per_hour` в Real Estate.
- Сборщики — компьютеры агентов: если ни одного нет на связи, поиск висит до 30 минут и
  заканчивается «не дождались».
