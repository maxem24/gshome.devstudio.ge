# Требования GS Home к API Real Estate

Для доработки API в репозитории `maxem24/real-estate.devstudio.ge` (делает отдельная сессия).

**Статус 2026-10-10:** R1–R4, R6, R7 сделаны в ветке `feature/listings-api` Real Estate
(коммит `c31c987`), на проде ещё нет; R5 — настройка клиента в админке. Дубли — решено двумя
метками, см. [[02_Решения]].
Текущий API — `~/Sites/real-estate.devstudio.ge/docs/RealEstate/16_API.md`.

## Почему нужно

Решение 2026-10-10: экран объявлений в GS Home работает **живыми запросами** к API — без своей
копии базы. Агент видит только объекты своего направления (продажа `deal_type_id=1` или
помесячная сдача `2`) и на каждом объявлении — метку принадлежности по телефону: «наш
сотрудник», «сотрудник связанной компании», «другая компания» (ТЗ 4.4, 5.7; правила —
[[05_Оргструктура]]). Номера сотрудников GS Home хранит у себя в E.164 (`+995…`).

Сейчас в API нет фильтра по телефону, поэтому нельзя показать «объявления моего коллеги» и
«только чужие», не перебирая всю базу.

## Что нужно

| # | Что | Подробно |
|---|---|---|
| R1 | Фильтр `phones` в `GET /listings` | Список номеров через запятую, E.164 (`+995555123456,+995599…`). Отдаёт объявления, у которых телефон контакта — один из них. Сравнение — по номеру, приведённому к E.164 (GE) на стороне Real Estate: `555 12 34 56`, `0555…`, `995…` — один номер. Замаскированные (`555402***`) не совпадают ни с чем |
| R2 | Фильтр `exclude_phones` | То же, наоборот: объявления, у которых телефон **не** из списка (и замаскированные/пустые тоже попадают). Нужен для «только другие компании» |
| R3 | Нормализованный телефон в ответе | `contact.phone_e164` — номер в E.164 или `null`, если номера нет или он замаскирован. Тогда GS Home не повторяет чужую логику разбора, а сравнивает строки |
| R4 | Длина списка | В группе может быть несколько сотен номеров (≈ 14 символов на номер). Принять список до 500 номеров в GET без 414/431 — проверить лимиты nginx/PHP на пути, указать предел в документации и ответ 422, если он превышен |
| R5 | Лимит для клиента GS Home | Поднять `rate_limit_per_minute` клиента до ~600 — это настройка в админке, не код. В документации API — рекомендация для «живых» клиентов |
| R6 | Объявления кластера | Для карточки: по `id` получить остальные объявления той же группы дублей с их телефонами — фильтр `cluster_id` в `GET /listings` (с `only_primary=0`) или список в `GET /listings/{id}`. Вариант — на усмотрение Real Estate |
| R7 | Фильтр по дате появления | `created_since` / `created_until` в `GET /listings` по `source_created_at` (ТЗ 4.5: «дата добавления»). Сейчас есть только `updated_since` — это другое |

Совместимость: в API неизвестный параметр — `422`, поэтому GS Home начнёт слать `phones` /
`exclude_phones` только после выкладки этой доработки.

## Открытый вопрос: дубли прячут объявления наших агентов

API по умолчанию отдаёт **одно главное объявление на кластер дублей** (`only_primary=1`) и
предпочитает собственника. Если агент выставил копию квартиры собственника, его объявление
почти наверняка не главное — в списке его не будет, и метка «наш сотрудник» появится реже,
чем ждут агенты (права при этом работают правильно).

Варианты (не решено, см. TODO в [[02_Решения]]):

- **а.** `phones` совпадает, если номер есть у **любого** объявления кластера, а отдаётся
  главное — с пометкой, какое объявление кластера совпало (`cluster.matched_listing_ids`).
- **б.** GS Home для фильтров по телефонам шлёт `only_primary=0` — в выдаче будут дубли.
- **в.** Метку считать по всему кластеру: на карточке и в списке — «в группе есть наш агент»
  (нужен R6 или поле с телефонами кластера в ответе).

От выбора зависит, как именно реализовать R1–R2, поэтому решить до доработки API.
